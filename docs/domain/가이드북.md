# 도메인 - 가이드북

# 배경

- **프로젝트 목표:** 사용자의 여행 조건과 취향에 맞는 관광 정보를 AI가 제공하고, 이를 가이드북 형태로 생성한다.
  - **핵심 결과 1:** 생성 요청부터 완료까지의 상태를 정의하고 사용자가 확인·재시도할 수 있게 한다.
  - **핵심 결과 2:** 동시 요청에도 작업이 유실되거나 중복 처리되지 않도록 한다.
  - **핵심 결과 3:** 생성 p95 처리 시간은 AI 구현 후 측정해 확정한다. 개별 AI 시도 타임아웃은 300초다.
- **문제 정의:**
  - 사용자가 여러 관광 콘텐츠를 직접 탐색하고 여행 정보를 하나의 문서로 정리하려면 많은 시간과 노력이 필요하다.
  - AI 생성과 관광 정보 조회는 시간이 걸리므로 하나의 HTTP 요청을 완료까지 유지하면 서버 자원을 오래 점유한다.
  - 상태·실패·재시도 규칙이 없으면 중복 요청과 생성권 중복 차감이 발생할 수 있다.
  - 장애 시에도 생성 작업, 가이드북 결과, 생성권 차감과 원장의 정합성을 유지해야 한다.
- **가설:** 생성을 비동기 작업으로 관리하고 멱등성·상태 조회·원자적 결과 반영을 제공하면 요청을 안정적으로 처리하고 사용자의 불확실성을 줄일 수 있다.

# 목표가 아닌 것

이번 프로젝트에서 다루지 않는 내용:

- **관련 장소 예약:** 관광지, 숙박, 식당, 교통 예약과 외부 예약 서비스 연동은 제외한다.
- **최초 생성 시 자연어 요청:** 최초 생성은 지역·일정·동행·인원·기본 취향을 사용한다. 자연어 피드백은 재생성에만 사용한다.
- **가이드북 직접·공동 편집:** 사용자가 일정과 HTML 본문을 직접 편집하거나 여러 사용자가 동시 편집하는 기능은 제외한다.
- **공유 가이드북 복사:** 가이드북과 일정을 복제하지 않고 회원별 보관 관계만 추가한다.
- **PDF 영구 보관:** MVP에서는 PDF를 요청 시 생성해 응답하며 파일·버전·다운로드 이력을 저장하지 않는다.

# 설계 및 기술 자료

## 공통 정책

- 모든 보호 API는 유효한 서버 세션을 가진 `ACTIVE` 회원만 이용할 수 있다.
- 보유 권한은 `member_guidebooks.member_id`와 회원 ID가 일치하고 `deleted_at IS NULL`인지로 판단한다.
- 가이드북 원본에 소유자·삭제 상태를 두지 않는다. 삭제는 회원의 보관 관계만 소프트 삭제한다.
- `Idempotency-Key`는 최초 생성과 재생성에 필수이며 최대 100자다.
- 회원당 `PENDING` 또는 `PROCESSING` 작업은 하나만 존재할 수 있다.
- 진행 작업은 생성권 1개가 논리적으로 예약된 것으로 판단한다. 실제 차감은 성공 시점에 수행한다.
- 공통 JSON·오류 규약은 [V3 API 명세서](../V3%20API%20명세서.md)를 따른다. PDF 성공 응답만 바이너리다.

## 데이터베이스 스키마(ERD)

### 주요 테이블

| 테이블 | 역할 | 핵심 컬럼·제약 |
|---|---|---|
| `generation_jobs` | AI 생성·재생성 작업과 요청 스냅샷 | `job_type`, `status`, `request_payload`, `attempt_count`, `idempotency_key`, `active_member_id UNIQUE` |
| `guidebooks` | 공유되는 가이드북 원본 | `content_html`, `version`, `region_id`, 여행 기간·동행·인원 |
| `member_guidebooks` | 회원별 가이드북 보관 관계 | `(member_id, guidebook_id) UNIQUE`, `acquisition_type`, `deleted_at` |
| `itinerary_days` | 일자별 일정 | `(guidebook_id, day_number) UNIQUE`, `itinerary_date` |
| `itinerary_items` | 방문 장소·순서·생성 시점 스냅샷 | `(itinerary_day_id, sequence) UNIQUE`, `tourism_content_id`, `place_snapshot` |
| `share_links` | 24시간 공유 토큰 | `guidebook_id`, `issued_by_member_id`, `token_hash UNIQUE`, `expires_at` |

### 생성 작업 상태

```text
PENDING -> PROCESSING -> COMPLETED
                    \-> FAILED
          \-> CANCELED
```

- `attempt_count=0`은 최초 시도다. 시스템 오류로 재시도할 때마다 1씩 증가하며 `0~3`을 허용한다.
- `FAILED`·`CANCELED`은 가이드북을 생성·변경하지 않고 생성권도 차감하지 않는다.
- 회원 탈퇴·대상 가이드북 삭제 시 취소를 요청하고 이후 도착한 AI 완료 응답은 반영하지 않는다.

### 가이드북 목록 API

- **API 명세**
  - `GET /guidebooks`
- **권한**
  - 로그인한 `ACTIVE` 회원
  - 본인의 활성 보관 관계만 조회 가능
- **구현 상세**
  - **요청:** Request Body 없음
  - **Query Parameter:** `cursor` 선택, `size` 기본 20·최소 1·최대 100
  - **처리 로직:**
    1. 세션에서 회원 ID를 조회한다.
    2. `member_guidebooks.member_id`가 회원 ID와 일치하고 `deleted_at IS NULL`인 관계를 조회한다.
    3. `member_guidebooks.created_at DESC, id DESC`로 정렬한다.
    4. 커서 이후 데이터를 `size + 1`건 조회해 `has_more`를 계산한다.
    5. 가이드북 요약·지역·`next_cursor`·`has_more`를 반환한다.
- **트랜잭션**
  - `@Transactional(readOnly = true)`
- **응답 상태**
  - 조회 성공: `200 OK`
  - 인증 실패: `401 AUTH_SESSION_REQUIRED`
  - 서버 내부 오류: `500 INTERNAL_SERVER_ERROR`

### 최초 가이드북 생성 접수 API

- **API 명세**
  - `POST /guidebook-generations`
  - Header: `Idempotency-Key` 필수, 최대 100자
- **권한**
  - 로그인한 `ACTIVE` 회원
  - 유효한 기본 취향이 설정된 회원
- **구현 상세**
  - **요청:**

    ```json
    {
      "region_code": "47",
      "start_date": "2026-10-12",
      "end_date": "2026-10-14",
      "companion": "FRIEND",
      "people_count": 2
    }
    ```

  - **처리 로직:**
    1. 지역, 날짜 형식·순서·최대 7일, 동행 Enum, 인원 범위를 검증한다.
    2. 회원 상태와 기본 취향을 확인한다.
    3. 멱등 키와 요청 내용을 비교한다. 같은 요청이면 기존 작업을 반환한다.
    4. 생성권 지갑 행을 잠그고 잔액을 확인한다.
    5. 회원의 `PENDING` 또는 `PROCESSING` 작업을 확인한다.
    6. 입력 조건과 기본 취향을 `request_payload`에 스냅샷으로 저장한다.
    7. `INITIAL`, `PENDING`, `guidebook_id=NULL`, `attempt_count=0`인 작업을 생성한다.
    8. 커밋 후 AI 생성을 트리거하고 `202 Accepted`를 반환한다.
- **트랜잭션**
  - 지갑 행 잠금·진행 작업 검사·`generation_jobs` 생성
  - AI 호출
- **응답 상태**
  - 접수·동일 요청 재조회: `202 Accepted`
  - 형식 오류: `400 COMMON_VALIDATION_ERROR`
  - 인증 실패: `401 AUTH_SESSION_REQUIRED`
  - 멱등 키 충돌: `409 IDEMPOTENCY_CONFLICT`
  - 다른 작업 진행 중: `409 GENERATION_IN_PROGRESS`
  - 생성권 부족: `422 CREDIT_INSUFFICIENT`
  - 여행 기간 오류: `422 GUIDEBOOK_INVALID_PERIOD`
  - 기본 취향 오류: `422 PREFERENCE_INVALID`
  - 서버 오류: `500 INTERNAL_SERVER_ERROR`

### 가이드북 재생성 접수 API

- **API 명세**
  - `POST /guidebooks/{guidebook_id}/regenerations`
  - Header: `Idempotency-Key` 필수, 최대 100자
- **권한**
  - 로그인한 `ACTIVE` 회원
  - 해당 가이드북을 활성 상태로 보유한 회원
  - 최초 생성 결과 화면에서만 요청 가능
- **구현 상세**
  - **요청:**

    ```json
    {
      "title": "경주 여유 여행",
      "feedback": "걷는 시간을 줄여 주세요."
    }
    ```

  - **요청 검증:** `title` 필수·최대 15자, `feedback` 필수·최대 200자, 공백 제거 후 빈 값 금지
  - **처리 로직:**
    1. 활성 보관, 기본 취향, 멱등 키, 생성권 잔액, 진행 작업을 검증한다.
    2. 제목·피드백·기존 여행 조건·현재 기본 취향을 `request_payload`에 저장한다.
    3. `REGENERATION`, `PENDING`, `guidebook_id=기존 ID`, `attempt_count=0`인 작업을 생성한다.
    4. 커밋 후 AI를 트리거하고 `202 Accepted`를 반환한다.
    5. 성공 시 같은 가이드북 ID의 제목·본문·일정을 교체하고 `version + 1`한다. 실패 시 기존 결과를 유지한다.
  - MVP에서는 화면 이탈을 서버 상태로 저장하지 않고 프론트엔드 흐름으로 진입점을 제한한다.
- **트랜잭션**
  - 접수: 지갑 잠금·진행 작업 검사·작업 생성
  - 완료: 본문·일정 교체·버전 증가·생성권 차감·원장·작업 완료
  - AI 호출은 트랜잭션 외부에서 수행
- **응답 상태**
  - 접수·동일 요청: `202 Accepted`
  - 형식 오류: `400 COMMON_VALIDATION_ERROR`
  - 인증 실패: `401 AUTH_SESSION_REQUIRED`
  - 미보유: `403 RESOURCE_FORBIDDEN`
  - 미존재: `404 RESOURCE_NOT_FOUND`
  - 멱등 키 충돌: `409 IDEMPOTENCY_CONFLICT`
  - 다른 작업 진행 중: `409 GENERATION_IN_PROGRESS`
  - 생성권 부족: `422 CREDIT_INSUFFICIENT`
  - 기본 취향 오류: `422 PREFERENCE_INVALID`
  - 서버 오류: `500 INTERNAL_SERVER_ERROR`

  - 해당 가이드북을 활성 상태로 보유한 회원

  - **트리거:** 사용자가 목록·상세에서 삭제를 선택하고 확인한다.

## 비동기 처리 설계

### 접수와 AI 호출

1. API 접수 트랜잭션에서 멱등 요청, 생성권 잔액, 진행 작업 유일성을 확인하고 `generation_jobs`를 저장한다.
2. DB 커밋 후 워커가 작업을 가져가 AI 서버를 호출한다.
3. AI 호출은 DB 트랜잭션 밖에서 수행해 장시간 잠금을 피한다.
4. 워커는 재시도 가능한 시스템 오류만 최대 3회 재시도한다.
5. 프론트엔드는 API-GDE-03을 폴링해 상태를 갱신한다.

### 결과 반영

- **최초 생성 성공:** 가이드북·일정·`CREATED` 보관 관계·생성권 차감·원장 기록·작업 `COMPLETED`를 한 트랜잭션으로 처리한다.
- **재생성 성공:** 제목·본문·일정 교체·`version + 1`·생성권 차감·원장 기록·작업 `COMPLETED`를 한 트랜잭션으로 처리한다.
- **실패·취소:** 기존 가이드북을 변경하지 않고 생성권을 차감하지 않는다.

## 이외 고려사항들 (Other Considerations)

- **성능:**
  - 생성 접수 API는 AI 응답을 기다리지 않고 `202 Accepted`를 반환한다.
  - AI 생성 처리 시간·성공률·타임아웃·재시도 횟수를 측정해 p95 목표와 동시 처리 한도를 확정한다.
  - 가이드북 목록은 커서 기반으로 조회하고 `member_guidebooks(member_id, deleted_at, created_at, id)` 인덱스를 사용한다.
  - PDF 생성 시간·메모리·동시 처리량을 측정한다. 임계치를 넘으면 `export_jobs`와 상태·파일 조회 API를 추가한다.
- **비동기 작업 안정성:**
  - AI 호출 오류를 재시도 가능한 시스템 오류와 사용자 입력 오류로 구분한다.
  - 개별 시도는 300초 후 타임아웃 처리하고, 시스템 오류는 최대 3회 재시도한다.
  - 서버 재시작 후 `PENDING`·`PROCESSING` 작업을 탐지·복구할 수 있어야 한다.
- **데이터 정합성:**
  - `Idempotency-Key`와 요청 내용을 함께 비교해 같은 요청은 기존 작업을 반환하고 다른 요청은 충돌로 처리한다.
  - `active_member_id UNIQUE`로 회원별 진행 작업을 하나로 제한한다.
  - 생성 성공 시 가이드북·일정·보관 관계·생성권 차감·원장·작업 완료를 한 트랜잭션으로 처리한다.
  - 재생성 실패 시 기존 결과를 유지하고, 취소 후 도착한 늦은 AI 응답은 반영하지 않는다.
  - `(member_id, guidebook_id) UNIQUE`로 같은 가이드북의 중복 가져오기를 방지한다.
- **보안:**
  - 공유 토큰은 충분히 긴 난수로 생성하고 원문 대신 해시를 DB에 저장한다.
  - 공유 링크 접근 시 만료 시각과 발급자의 활성 보관 관계를 확인한다.
  - 공유 토큰 원문, 사용자 피드백, AI 원문 응답, 개인정보를 로그에 남기지 않는다.

## 용어 정의 (Glossary)

- **가이드북(Guidebook):** 여행 조건과 취향을 기준으로 AI가 생성한 본문과 일정의 집합.
- **생성 작업(Generation Job):** AI 생성 요청의 입력, 상태, 시도 횟수, 결과·오류를 관리하는 비동기 처리 단위.
- **생성 작업 상태:**
  - `PENDING`: 작업이 접수되어 처리를 기다리는 상태
  - `PROCESSING`: AI 생성 작업을 처리 중인 상태
  - `COMPLETED`: 결과 반영과 생성권 차감이 완료된 상태
  - `FAILED`: 재시도 후에도 생성에 실패한 상태
  - `CANCELED`: 회원 탈퇴·가이드북 삭제 등으로 작업이 취소된 상태
- **작업 유형(Job Type):**
  - `INITIAL`: 새 가이드북을 생성하는 작업
  - `REGENERATION`: 기존 가이드북의 제목·본문·일정을 교체하는 작업
- **보관 관계(Member Guidebook):** 회원이 특정 가이드북을 보유하고 조회할 수 있음을 표현하는 관계.
- **보관 유형(Acquisition Type):**
  - `CREATED`: 회원의 AI 요청으로 최초 생성한 가이드북
  - `IMPORTED`: 공유 링크로 가져온 가이드북
- **논리적 생성권 예약:** 생성권을 미리 차감하지 않지만 `PENDING`·`PROCESSING` 작업이 생성권 1개를 사용할 예정이라고 판단하는 규칙. 성공 시 차감하고 실패·취소 시 차감하지 않는다.
- **멱등 키(Idempotency-Key):** 같은 요청의 재전송이 새 작업이나 중복 차감을 만들지 않도록 클라이언트가 제공하는 요청 식별자.
- **멱등 키 충돌:** 같은 멱등 키를 이전과 다른 요청 내용에 사용한 상태. `409 IDEMPOTENCY_CONFLICT`로 처리한다.
- **장소 스냅샷(Place Snapshot):** 외부 관광 콘텐츠가 변경되어도 생성 시점의 가이드북 내용을 유지하기 위해 일정 항목에 저장하는 장소 정보.
- **공유 토큰:** 가이드북 ID를 직접 노출하지 않고 미리보기·가져오기를 제공하기 위한 24시간 만료 난수 값.

# 테크스펙 문서 작성

# 도메인 - 가이드북 V1

# 배경

- **프로젝트 목표:** 사용자의 여행 조건과 기본 취향에 맞는 관광 정보를 AI가 제공하고, 이를 가이드북 형태로 생성한다.
  - **핵심 결과 1:** 생성 요청부터 완료까지의 상태를 정의하고 사용자가 조회할 수 있게 한다.
  - **핵심 결과 2:** 멱등 키와 DB 제약으로 작업 중복과 무료 생성권 중복 차감을 방지한다.
  - **핵심 결과 3:** 개별 AI 시도를 300초로 제한하고 시스템 오류는 최대 3회 재시도한다.
- **문제 정의:**
  - 사용자가 직접 관광 정보를 조사하고 일정을 정리하려면 많은 시간과 노력이 필요하다.
  - AI 생성은 시간이 걸리므로 완료까지 HTTP 연결을 유지하면 서버 자원을 오래 점유한다.
  - 장애·재시도·중복 요청을 고려하지 않으면 가이드북 결과와 생성권 원장의 정합성이 깨질 수 있다.
- **가설:** AI 생성을 비동기 작업으로 관리하고 멱등성·상태 조회·원자적 결과 반영을 제공하면 요청을 안정적으로 처리할 수 있다.

  - [V3 API 명세서](../V3%20API%20명세서.md) - 필드·응답 규약 참고
  - [테이블정의서](../테이블정의서.md)

# 목표가 아닌 것

이번 V1에서 다루지 않는 내용:

- **관련 장소 예약:** 관광지·숙박·식당·교통 예약과 외부 예약 서비스 연동
- **가이드북 직접 편집:** 사용자의 일정·HTML 본문 편집과 공동 편집
- **재생성:** 제목·자연어 피드백을 이용한 AI 재생성은 V3에서 제공한다.
- **공유·가져오기:** 공유 링크, 미리보기, 다른 회원의 가이드북 가져오기는 V3에서 제공한다.
- **유료 생성권·결제:** V1은 무료 생성권만 사용한다. 생성권 상품·주문·PG 결제는 V2에서 제공한다.
- **PDF 영구 보관:** PDF는 요청 시 생성해 응답하며 파일·버전·다운로드 이력을 저장하지 않는다.

# 설계 및 기술 자료

## V1 공통 정책

- 보호 API는 유효한 서버 세션을 가진 `ACTIVE` 회원만 이용할 수 있다.
- 가이드북 보유는 `member_guidebooks.member_id`와 회원 ID가 일치하고 `deleted_at IS NULL`인지로 판단한다.
- V1의 `member_guidebooks.acquisition_type`은 `CREATED`만 사용한다. `IMPORTED`는 V3에서 사용한다.
- 생성 요청은 최대 100자의 `Idempotency-Key`를 필수로 받는다.
- 같은 회원의 같은 멱등 키·같은 본문은 기존 작업을 반환하고, 같은 키·다른 본문은 `409 IDEMPOTENCY_CONFLICT`로 처리한다. 다른 회원의 같은 키는 별도 요청이다. 키는 표시 가능한 ASCII 1~100자이며 대소문자를 구분한다.
- 회원당 `PENDING` 또는 `PROCESSING` 작업은 하나만 존재할 수 있다.
- 진행 작업은 무료 생성권 1개가 논리적으로 예약된 상태다. 성공 시 차감하고 실패·취소 시 차감하지 않는다.

- `share_links`: V3 공유 링크 도입 시 사용
- `member_guidebooks.acquisition_type=IMPORTED`: V3 가져오기 도입 시 사용

- `credit_products`, `orders`, `payment_attempts`: V2 유료 생성권·결제 도입 시 사용

## 도메인 간 인터페이스

- **회원 도메인:** 로그인 회원의 `ACTIVE` 상태와 현재 기본 취향을 제공한다.
- **관광 콘텐츠 도메인:** TourAPI 원본 중 서비스가 허용한 6개 관광 분류를 최소 필드로 정규화·주기 동기화해 지도와 AI 입력에 제공하고, 일정 저장 시 `tourism_content_id`와 스냅샷을 나눈다. V1은 MySQL을 조회하며, V2 Redis는 동일 지역 AI 후보 조회가 실제 병목일 때 파생 결과 캐시로만 검토한다.
- **생성권·결제 도메인:**
  - 접수 시 무료 생성권 잔액을 확인하고 지갑 행 잠금을 제공한다.
  - 성공 시 `generation_job_id`를 원인으로 생성권 1개를 멱등하게 차감하고 원장을 남긴다.
  - V1은 같은 모놀리식·MySQL 내의 짧은 트랜잭션으로 가이드북 결과와 생성권 차감을 함께 처리한다.

## 생성 작업 상태

```text
PENDING -> PROCESSING -> COMPLETED
   ^          |      \-> FAILED
   |----------|          (재시도 가능한 실패: 5/10/20초 대기)
          \-> CANCELED
```

- `attempt_count=0`은 최초 시도다. 시스템 오류로 재시도할 때마다 1씩 증가하며 `0~3`을 허용한다.
- 워커는 60초 lease를 15초마다 연장하고, 개별 AI 시도는 300초로 제한한다. lease 만료 자체는 재시도 횟수를 증가시키지 않는다.
- 선점·재선점마다 `lease_token`을 교체하고 `lease_version`을 증가시킨다. heartbeat와 결과 저장은 둘 다 일치해야 한다.
- 재시도 가능한 실패는 5·10·20초 뒤 `PENDING`으로 전환한다. 재시도 불가능한 실패나 최대 횟수 소진은 `FAILED`로 종료한다.
- `COMPLETED` 전환 시 가이드북·일정·보관 관계를 저장하고 무료 생성권 1개를 차감한다.
- `FAILED`·`CANCELED`은 가이드북을 생성하지 않고 생성권도 차감하지 않는다.

### 가이드북 목록 API

- **API 명세:** `GET /guidebooks`
- **권한:** 로그인한 `ACTIVE` 회원, 본인의 활성 보관 관계만 조회
- **구현 상세:**
  - **요청:** Request Body 없음, `cursor` 선택, `size` 기본 20·1~100
  - **처리 로직:**
    1. 세션에서 회원 ID를 조회한다.
    2. `member_guidebooks.member_id`가 회원 ID와 일치하고 `deleted_at IS NULL`인 관계를 조회한다.
    3. `member_guidebooks.created_at DESC, id DESC`로 정렬한다.
    4. `size + 1`건으로 `has_more`를 계산하고 `next_cursor`를 반환한다.
- **트랜잭션:** `@Transactional(readOnly = true)`
- **응답 상태:** `200 OK`, `401 AUTH_SESSION_REQUIRED`, `500 INTERNAL_SERVER_ERROR`

### 최초 가이드북 생성 접수 API

- **API 명세:** `POST /guidebook-generations`, `Idempotency-Key` 필수
- **권한:** 로그인한 `ACTIVE` 회원, 유효한 기본 취향이 설정된 회원
- **구현 상세:**
  - **요청:**

    ```json
    {
      "region_code": "47",
      "start_date": "2026-10-12",
      "end_date": "2026-10-14",
      "companion": "FRIEND",
      "people_count": 2
    }
    ```

  - **처리 로직:**
    1. 인증과 허용 필드·형식을 검사하고 멱등 키의 기존 요청을 먼저 비교한다. 동일 요청은 현재 작업을 반환한다.
    2. 새 요청에만 서울 기준 오늘~1년·1~7일, ALONE=1/FRIEND=2~4/COUPLE=2/FAMILY=2~6/GROUP=2~10을 검증한다.
    3. 회원 행을 잠그고 ACTIVE·요청 세션을 재검증하며 현재 취향 전체를 읽는다.
    4. 다음으로 무료 생성권 지갑 행을 잠그고 `credit_balance >= 1`인지 확인한다.
    5. 회원의 `PENDING`·`PROCESSING` 작업을 확인한다.
    6. 입력 조건과 취향을 `request_payload`에 저장한다.
    7. `job_type=INITIAL`, `status=PENDING`, `guidebook_id=NULL`, `attempt_count=0`인 작업을 생성한다.
    8. 커밋 후 AI 생성을 트리거하고 `202 Accepted`를 반환한다.
- **트랜잭션:** 지갑 행 잠금·진행 작업 검사·`generation_jobs` 생성. AI 호출은 커밋 이후에 수행한다.
- **응답 상태:**
  - 접수·동일 요청: `202 Accepted`
  - 형식 오류: `400 COMMON_VALIDATION_ERROR`
  - 인증 실패: `401 AUTH_SESSION_REQUIRED`
  - 멱등 키 충돌: `409 IDEMPOTENCY_CONFLICT`
  - 다른 작업 진행 중: `409 GENERATION_IN_PROGRESS`
  - 무료 생성권 부족: `422 CREDIT_INSUFFICIENT`
  - 여행 기간 오류: `422 GUIDEBOOK_INVALID_PERIOD`
  - 기본 취향 오류: `422 PREFERENCE_INVALID`
  - 서버 오류: `500 INTERNAL_SERVER_ERROR`

### 생성 상태 조회 API

- **API 명세:** `GET /guidebook-generations/{job_id}`
- **권한:** 로그인한 `ACTIVE` 회원, 본인이 요청한 작업만 조회
- **구현 상세:**
  - **요청:** Request Body 없음
  - **처리 로직:**
    1. 작업의 `member_id`와 세션 회원 ID를 비교한다.
    2. 현재 명세의 상태·시도 횟수·실패 정보를 반환한다. progress/retryable은 AI/FE 계약 전 미제공이다.
    3. `COMPLETED`면 결과 `guidebook_id`를 반환한다.
  - 프론트엔드는 생성 화면에서 폴링하고 백그라운드 복귀 후 재조회한다.
- **트랜잭션:** `@Transactional(readOnly = true)`
- **응답 상태:** `200 OK`, `401 AUTH_SESSION_REQUIRED`, `403 RESOURCE_FORBIDDEN`, `404 RESOURCE_NOT_FOUND`, `500 INTERNAL_SERVER_ERROR`

### 가이드북 상세 API

- **API 명세:** `GET /guidebooks/{guidebook_id}`
- **권한:** 로그인한 `ACTIVE` 회원, 활성 보관 관계를 가진 회원
- **구현 상세:**
  - **요청:** Request Body 없음
  - **처리 로직:** 회원·가이드북의 활성 보관 관계를 한 번에 조회하고 제목·시작일·종료일·동행·인원·버전·수정 시각·HTML 본문을 반환한다. 지역 정보는 지역 도메인 조회 기능 연동 후 제공한다.
- **트랜잭션:** `@Transactional(readOnly = true)`
- **응답 상태:** `200 OK`, `401 AUTH_SESSION_REQUIRED`, `403 RESOURCE_FORBIDDEN`(ONBOARDING 등 허용되지 않은 회원 상태, 공통 인가 정책 구현 후 적용), `404 RESOURCE_NOT_FOUND`(없는 가이드북·미보관·삭제된 관계·타인 보관), `500 INTERNAL_SERVER_ERROR`

### 일정 조회 API

- **API 명세:** `GET /guidebooks/{guidebook_id}/itinerary`
- **권한:** 로그인한 `ACTIVE` 회원, 활성 보관 관계를 가진 회원
- **구현 상세:**
  - **요청:** Request Body 없음
  - **처리 로직:**
    1. 활성 보관 관계를 확인한다.
    2. `itinerary_days`를 `day_number ASC`, 항목을 `sequence ASC`로 조회한다.
    3. `tourism_content_id`와 생성 시점의 `place_snapshot`을 함께 반환한다.
  - 일정 항목은 스냅샷 구성요소이므로 별도 단건 API를 제공하지 않는다.
- **트랜잭션:** `@Transactional(readOnly = true)`
- **응답 상태:** `200 OK`, `401 AUTH_SESSION_REQUIRED`, `403 RESOURCE_FORBIDDEN`, `404 RESOURCE_NOT_FOUND`, `500 INTERNAL_SERVER_ERROR`

### PDF 다운로드 API

- **API 명세:** `POST /guidebooks/{guidebook_id}/exports`
- **권한:** 로그인한 `ACTIVE` 회원, 활성 보관 관계를 가진 회원
- **구현 상세:**
  - **트리거:** 사용자가 상세·HTML 뷰어에서 `PDF 다운로드`를 누른다.
  - **요청:** `{ "format": "PDF" }`
  - **처리 로직:**
    1. 활성 보관 관계를 확인한다.
    2. HTML·일정·이미지를 조회하고 HTML을 정제한다.
    3. PDF로 렌더링해 영구 저장하지 않고 같은 HTTP 응답으로 반환한다.
  - **성공 응답:** `200 OK`, `Content-Type: application/pdf`, `Content-Disposition: attachment`
- **트랜잭션:** DB 조회만 `readOnly`로 처리하고 PDF 렌더링은 트랜잭션 밖에서 수행한다.
- **응답 상태:** `200 OK`, `400 COMMON_VALIDATION_ERROR`, `401 AUTH_SESSION_REQUIRED`, `403 RESOURCE_FORBIDDEN`, `404 RESOURCE_NOT_FOUND`, `500 PDF_EXPORT_FAILED`, `503 SERVICE_UNAVAILABLE`

- **API 명세:** `GET /guidebooks/{guidebook_id}/viewer`
- **권한:** 로그인한 `ACTIVE` 회원, 활성 보관 관계를 가진 회원

### 가이드북 삭제 API

- **API 명세:** `DELETE /guidebooks/{guidebook_id}`
- **권한:** 로그인한 `ACTIVE` 회원, 활성 보관 관계를 가진 회원
- **구현 상세:**
  - **요청:** Request Body 없음
  - **처리 로직:**
    1. 회원의 활성 `member_guidebooks` 관계를 조회한다.
    2. 해당 관계의 `deleted_at`을 현재 시각으로 갱신한다.
    3. 원본 가이드북·일정은 즉시 물리 삭제하지 않는다.
- **트랜잭션:** 활성 보관 관계 확인과 `deleted_at` 갱신
- **응답 상태:** `204 No Content`, `401 AUTH_SESSION_REQUIRED`, `403 RESOURCE_FORBIDDEN`, `404 RESOURCE_NOT_FOUND`, `500 INTERNAL_SERVER_ERROR`

## 무료 생성권 처리

### 무료 생성권 지급

- 가입 TX에서 가입월 3회, 이후 서울 달력월마다 3회 누적 지급한다. 이월 가능·월말 초기화 없음·제품상 상한 없음이다.
- 가입월도 monthly-free:{memberId}:{yyyyMM}를 사용해 중복 지급을 막고 누락 월을 재대사한다. 탈퇴 시 취소·잔액 회수, 재가입은 새 회원 3회다.
- 무료 지급도 `credit_transactions`에 원인별 멱등 키와 처리 후 잔액을 기록한다.
- V1에서는 상품·주문·결제 데이터를 생성하지 않는다.

### 생성 성공 차감

1. 접수 시 지갑 행을 잠그고 잔액과 진행 작업을 확인한다.
2. `PENDING`·`PROCESSING` 작업은 생성권 1개의 논리적 예약으로 판단한다.
3. AI 성공 시 회원→지갑→작업을 잠그고 lease_token·lease_version·attempt_count·상태·취소 여부를 재검증한 뒤 생성권 1개를 차감한다.
4. `generation_job_id`를 원인으로 사용한 원장을 생성해 중복 차감을 막는다.
5. 가이드북·일정·`CREATED` 보관 관계·차감 원장·작업 `COMPLETED`를 한 트랜잭션으로 처리한다.
6. 실패·취소 시 잔액을 변경하지 않는다.

## 비동기 처리 설계

1. 접수 트랜잭션에서 멱등 요청, 무료 생성권 잔액, 진행 작업 유일성을 확인하고 `generation_jobs`를 저장한다.
2. DB 커밋 후 워커가 작업을 가져가 AI 서버를 호출한다.
3. AI 호출은 DB 트랜잭션 밖에서 수행한다.
4. 워커는 재시도 가능한 시스템 오류만 최대 3회 재시도한다.
5. 프론트엔드는 상태 조회 API를 폴링하고 백그라운드 복귀 후 재조회한다.

## 이외 고려사항들 (Other Considerations)

- **성능:** AI 생성 시간·성공률·타임아웃·재시도 횟수를 측정해 p95 목표와 동시 작업 한도를 확정한다.
- **장애 복구:** 서버 재시작 후 `PENDING`·`PROCESSING` 작업을 탐지하고 재개·실패 처리할 수 있어야 한다.
- **데이터 정합성:** DB 트랜잭션·유일 제약·원장 멱등성으로 작업·결과·생성권의 중복 반영을 막는다.
- **보안:** 사용자 취향, AI 요청·응답 원문, 개인정보를 로그에 남기지 않고 AI HTML을 정제한다.
- **확장성:** V1은 DB 기반 작업 관리로 시작하고, 작업량과 유실 위험이 커지면 메시지 큐 도입을 검토한다.

## 용어 정의 (Glossary)

- **가이드북:** 여행 조건과 취향을 기준으로 AI가 생성한 본문과 일정의 집합.
- **생성 작업:** AI 생성 요청의 입력, 상태, 시도 횟수, 결과·오류를 관리하는 비동기 처리 단위.
- **생성 작업 상태:**
  - `PENDING`: 접수 후 처리 대기
  - `PROCESSING`: AI 작업 처리 중
  - `COMPLETED`: 결과 저장과 무료 생성권 차감 완료
  - `FAILED`: 최종 생성 실패
  - `CANCELED`: 작업 취소
- **논리적 생성권 예약:** 생성권을 미리 차감하지 않지만 진행 작업이 생성권 1개를 사용할 예정이라고 판단하는 규칙.
- **멱등 키:** 같은 요청의 재전송이 새 작업이나 중복 차감을 만들지 않게 하는 요청 식별자.
- **장소 스냅샷:** 외부 관광 콘텐츠가 변되어도 생성 시점의 일정 내용을 유지하기 위해 저장하는 장소 정보.

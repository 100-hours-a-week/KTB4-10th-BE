# 0단계 프로젝트 요구사항 분석 — V3 기준

> 기준 범위: `10팀_Figma > 화면설계서 > V3` 프레임 내부. V1·V2는 V3에서 문구가 생략되어 해석이 불가능한 경우에만 참고하며, V1·V2의 기능을 V3 범위에 자동 포함하지 않는다.
>
> 목적: 화면을 그대로 나열하는 문서가 아니라, 이후 ERD·API·기술 선정·테크스펙이 동일한 도메인 용어와 요구사항 ID에서 출발하도록 만드는 설계 초안이다.

## 1. 서비스와 V3 범위

콜인원은 사용자의 여행 취향, 여행 조건, 현재 위치를 바탕으로 국내 문화유산·행사/축제·명소를 탐색하고, 개인화된 가이드북과 일정을 생성·관리·공유하며, 여행 종료 후 장소를 평가하고 평가 기반 랭킹을 제공하는 서비스다.

### 1.1 V3 핵심 사용자 흐름

1. 사용자가 카카오 또는 구글 OAuth로 로그인한다.
2. 신규 사용자는 여행 취향과 여행 스타일을 선택하고 저장한다.
3. 사용자는 지도에서 현재 위치 주변 3km의 장소를 탐색한다.
4. 사용자는 정보 탭에서 장소·행사를 검색하고 지역·월·카테고리로 필터링한다.
5. 사용자는 여행 지역·기간·동행·인원·취향을 입력해 가이드북 생성을 요청한다.
6. 시스템은 장소 탐색, 기간 내 행사 확인, 일정 조합을 비동기로 수행한다.
7. 사용자는 생성된 가이드북과 Day별 방문 순서를 확인하고 지도에 일정 핀을 표시한다.
8. 사용자는 가이드북을 앱 링크 또는 파일로 공유하고, 수신자는 자신의 가이드북에 추가한다.
9. 여행 종료 후 사용자는 일정에 포함된 장소를 방문 순서대로 평가한다.
10. 시스템은 별점과 평가 수를 보정해 월간·주간 장소 랭킹을 제공한다.
11. 사용자는 마이페이지에서 프로필, 취향, 알림 설정, 계정 기능을 관리한다.

### 1.2 범위 해석 원칙

- `맵`, `정보`, `가이드`, `마이페이지`는 화면 진입점이며 각각 하나의 서버 도메인이 되는 것은 아니다.
- 지도와 정보 화면은 모두 `장소 카탈로그`를 조회하지만 표현과 조회 조건이 다르다.
- 마이페이지는 회원·취향·가이드북·알림 데이터를 조합하는 조회 화면이다. 별도의 핵심 원장 데이터를 소유하지 않는다.
- 랭킹은 장소 원본 데이터가 아니라 제출된 평가를 기반으로 계산되는 파생 결과다.
- 공유로 추가한 가이드북은 원본과 구분되는 수신자 소유 데이터다.

## 2. 도메인 분류와 경계

### 2.1 도메인 지도

| 구분 | 도메인 | 책임 | 핵심 객체 | 직접 의존 |
|---|---|---|---|---|
| 핵심 | 가이드북·일정 | 여행 조건과 취향을 바탕으로 일자별 방문 계획 생성·보관 | Guidebook, ScheduleDay, ScheduleItem, GenerationJob | 회원, 취향, 장소 |
| 핵심 | 평가·랭킹 | 여행 종료 후 실제 방문 장소 평가와 보정 순위 산정 | ReviewSession, PlaceRating, RankingSnapshot | 가이드북, 장소, 회원 |
| 지원 | 장소 카탈로그 | 문화유산·행사/축제·명소의 표준 정보 관리 | Place, EventPeriod, Category, Region, Media | 외부 관광 데이터 |
| 지원 | 탐색·관심 | 지도/정보 검색, 필터, 주변 탐색, 관심 장소 관리 | FavoritePlace, SearchCondition, MapQuery | 장소, 회원 |
| 지원 | 취향 | 계정 기본 취향과 여행별 취향 입력 관리 | PreferenceProfile, PreferenceOption | 회원 |
| 지원 | 공유 | 공유 링크 발급, 수신, 중복 방지, 사본 생성 | ShareLink, GuidebookImport | 가이드북, 회원 |
| 지원 | 알림 | 인앱 알림, 읽음 상태, 푸시 수신 설정 관리 | Notification, NotificationSetting | 회원, 가이드북 |
| 일반 | 회원·인증 | OAuth 인증, 세션, 계정 상태, 프로필 관리 | Member, SocialAccount, Session | OAuth 제공자 |
| 일반 | 위치·외부 연동 | 현재 위치, 지도 SDK, 관광 데이터·이미지 연동 | ExternalPlaceRef, SyncMetadata | Kakao Map, TourAPI |
| 조회 조합 | 마이페이지 | 여러 도메인의 사용자별 요약을 조합해 제공 | MyPageView | 회원, 취향, 가이드북, 알림 |

### 2.2 도메인 간 소유권 원칙

- 회원 도메인은 `memberId`와 계정 상태를 소유한다. 다른 도메인은 회원 프로필을 복제해 원장으로 삼지 않는다.
- 장소 카탈로그는 장소의 표준 식별자와 현재 정보를 소유한다.
- 가이드북은 생성 당시 여행 결과를 소유한다. 외부 장소 데이터가 변경되어도 일정의 순서와 사용자 소유권이 훼손되면 안 된다.
- 평가 도메인은 별점을 소유하고 장소 도메인은 별점을 직접 수정하지 않는다.
- 랭킹은 평가 데이터를 읽어 계산하지만 평가 원장을 수정하지 않는다.
- 공유 도메인은 링크와 수신 기록을 소유하고, 수신 완료 후 생성된 사본은 가이드북 도메인이 소유한다.
- 알림은 다른 도메인의 사건을 전달하지만 가이드북 생성이나 공유 성공 여부의 원장이 아니다.
- 마이페이지 응답은 조합 결과이며 회원·가이드북·알림의 상태를 직접 변경하지 않는다.

## 3. 도메인 사전

| 용어 | 정의 | 식별 기준/주요 속성 | 혼동 방지 |
|---|---|---|---|
| 회원(Member) | OAuth 인증을 통과하고 서비스 데이터를 소유하는 사용자 | memberId, status, joinedAt | OAuth 제공자의 사용자 객체와 구분한다. |
| 소셜 계정(SocialAccount) | 회원과 OAuth 제공자 계정을 연결하는 정보 | provider, providerSubject, memberId | 이메일만으로 동일 회원을 판단하지 않는다. |
| 계정 상태 | 회원의 서비스 이용 가능 상태 | ACTIVE, WITHDRAWING, WITHDRAWN | 로그아웃은 계정 상태 변경이 아니다. |
| 취향 프로필(PreferenceProfile) | 이후 가이드북 생성에 기본으로 사용하는 계정 단위 선호 | 선호 카테고리, 세부 선호, 여행 스타일 | 특정 가이드북 생성 화면에서 변경한 취향과 구분한다. |
| 여행별 취향 | 한 번의 가이드북 생성 요청에만 적용되는 취향 스냅샷 | generationRequestId, optionIds | 저장해도 기본 취향을 자동 변경하지 않는다. |
| 장소(Place) | 지도·정보·일정·평가에서 공통 참조하는 방문 대상 | placeId, externalId, category, region, coordinates | 행사도 방문 장소로 평가할 수 있으므로 공통 식별자가 필요하다. |
| 행사 기간(EventPeriod) | 행사·축제의 시작/종료와 상태 계산에 사용하는 기간 | startsAt, endsAt, timezone | 일반 명소의 운영시간과 구분한다. |
| 장소 카테고리 | 장소의 대분류 | HERITAGE, EVENT_FESTIVAL, ATTRACTION | 관심 장소는 카테고리가 아니라 회원-장소 관계다. |
| 관심 장소(FavoritePlace) | 회원이 저장한 장소 관계 | memberId + placeId | 장소 자체의 속성이 아니다. |
| 여행 조건(TripCondition) | 가이드북 생성을 위한 지역·기간·동행·인원 입력 | region, startDate, endDate, companionType, headcount | 계정 기본 취향과 분리한다. |
| 생성 요청(GenerationJob) | 가이드북 생성의 비동기 작업 단위 | jobId, memberId, idempotencyKey, status, progressStep | 완성된 가이드북과 구분한다. |
| 가이드북(Guidebook) | 회원이 소유하는 하나의 여행 계획 묶음 | guidebookId, ownerId, title, period, sourceType | 공유 링크 자체가 아니다. |
| 일정 일차(ScheduleDay) | 여행 기간 중 특정 날짜의 일정 단위 | guidebookId, dayNumber, visitDate | `Day 1`과 실제 날짜를 모두 보관한다. |
| 일정 항목(ScheduleItem) | 특정 Day에 방문할 장소와 순서 | scheduleDayId, placeId, visitOrder, pinMetadata | 장소 카탈로그 원본과 별도다. |
| 핀 메타정보 | 일정 장소를 지도에 표현하는 가이드북 종속 정보 | 색상, 순서, 상태, 표시 조건 | 단순히 기존 핀 색만 바꾸는 값으로 취급하지 않는다. |
| 공유 링크(ShareLink) | 특정 가이드북을 수신할 수 있는 24시간 유효 토큰 | token, guidebookId, issuerId, expiresAt, status | URL 문자열을 DB 기본키로 사용하지 않는다. |
| 가이드북 가져오기(GuidebookImport) | 수신자가 공유 가이드북을 자신의 소유로 추가한 기록 | recipientId, shareLinkId, copiedGuidebookId | 링크 조회와 실제 추가 완료를 구분한다. |
| 평가 세션(ReviewSession) | 한 가이드북의 방문 장소를 순서대로 평가하는 진행 단위 | memberId, guidebookId, status, currentIndex | 장소 한 건의 별점과 구분한다. |
| 장소 평가(PlaceRating) | 회원이 특정 여행에서 방문한 장소에 제출한 별점 | memberId, guidebookId, scheduleItemId, placeId, score | 자유 리뷰 텍스트는 V3 범위에 없다. |
| 평가 건너뛰기 | 특정 장소의 별점을 입력하지 않고 다음으로 이동하는 선택 | skippedAt 또는 미생성 | 전체 평가 안내 건너뛰기와 구분한다. |
| 평가 안내 거절 | 최초 평가 모달에서 전체 평가를 진행하지 않는 선택 | reviewSession.promptDismissedAt | 자동 모달은 재노출하지 않지만 가이드북에서 수동 진입할 수 있다. |
| 랭킹(Ranking) | 같은 집계 조건의 장소를 보정 점수로 정렬한 결과 | periodType, periodStart, region, placeId, rank | 장소에 영구 저장되는 고정 순위가 아니다. |
| 알림(Notification) | 사용자에게 발생한 사건을 전달하는 계정별 인앱 항목 | notificationId, memberId, type, targetId, readAt | 푸시 메시지 전송 성공 여부와 구분한다. |
| 푸시 설정 | 여행 일정 관련 OS 푸시 수신 여부 | memberId, enabled | 인앱 알림과 토스트는 설정과 무관하게 표시한다. |

## 4. 도메인별 비즈니스 규칙

### 4.1 회원·인증

- **BR-AUTH-01** V3 로그인 제공자는 카카오와 구글이다.
- **BR-AUTH-02** 회원 식별은 `(provider, providerSubject)` 조합으로 수행하며 이메일 단독 매칭을 금지한다.
- **BR-AUTH-03** 로그인 요청 중 소셜 로그인 버튼을 비활성화하여 중복 인증을 방지한다.
- **BR-AUTH-04** OAuth 취소와 인증/서버 실패를 구분해 안내한다.
- **BR-AUTH-05** 신규 회원은 취향 설정 완료 전 핵심 탭으로 진입할 수 없다.
- **BR-AUTH-06** 기존 회원은 저장된 취향이 있으면 로그인 후 MAP-01로 이동한다.
- **BR-AUTH-07** 로그아웃은 세션만 폐기하며 가이드북·평가·관심 장소를 삭제하지 않는다.
- **BR-AUTH-08** 회원 탈퇴는 재확인 후 처리하고, 성공한 경우 복구할 수 없다.
- **BR-AUTH-09** 탈퇴 처리 일부만 성공한 상태가 노출되지 않도록 단일 상태 전이 또는 보상 처리가 필요하다.
- **BR-AUTH-10** 프로필 정보가 OAuth 응답에 없을 때 필드별 기본 표시값을 사용한다.

### 4.2 취향

- **BR-PREF-01** 최초 취향 설정은 최소 선택 조건을 충족해야 저장할 수 있다.
- **BR-PREF-02** 취향은 대분류, 선택한 대분류의 세부 선호, 여행 스타일로 구성한다.
- **BR-PREF-03** 선택 가능한 최소·최대 개수는 서버 정책과 화면 검증값을 동일하게 유지한다.
- **BR-PREF-04** 계정 기본 취향은 이후 가이드북 생성의 기본값으로 사용한다.
- **BR-PREF-05** 가이드북 생성 과정에서 수정한 여행별 취향은 해당 생성 요청에만 반영하고 계정 기본 취향을 갱신하지 않는다.
- **BR-PREF-06** 가이드북 생성에 사용하는 취향은 요청 시점 스냅샷으로 보관한다.
- **BR-PREF-07** 추천 가중치의 구체적 값은 추천 테크스펙에서 버전 관리한다.

### 4.3 장소 카탈로그·정보 탐색

- **BR-PLACE-01** 장소 대분류는 문화유산, 행사·축제, 명소의 세 가지다.
- **BR-PLACE-02** 장소는 내부 `placeId`와 외부 데이터 원본 식별자를 함께 가진다.
- **BR-PLACE-03** 정보 검색어는 최대 10자이며 엔터 입력 시 검색을 실행한다.
- **BR-PLACE-04** 일반 목록의 검색어, 지역, 월, 카테고리는 AND 조건으로 적용한다.
- **BR-PLACE-05** 지역은 전체와 17개 광역 시·도를 행정구역 코드 순으로 제공한다.
- **BR-PLACE-06** 월은 전체와 1~12월을 제공한다. 행사·축제는 개최 기간과 겹치는 월을 기준으로 필터링한다.
- **BR-PLACE-07** 카테고리 선택 시 해당 카테고리만 표시한다.
- **BR-PLACE-08** 한 페이지에 최대 5개 카드를 제공하고 순번형 페이지네이션을 사용한다.
- **BR-PLACE-09** 검색·필터 변경 시 첫 페이지로 이동한다. 상세에서 복귀하면 검색어·필터·페이지·스크롤을 복원한다.
- **BR-PLACE-10** 검색 결과 없음과 통신 실패를 서로 다른 상태로 안내한다.
- **BR-PLACE-11** 행사 상태는 Asia/Seoul 기준 현재 시각과 시작·종료 시각으로 예정·진행 중·종료를 계산한다.
- **BR-PLACE-12** 종료일만 제공될 경우 종료일 23:59:59까지 유효한지 외부 데이터 정책을 확정해야 한다.
- **BR-PLACE-13** 상세에는 정보 제공처, 원본 갱신일, 고정 면책 안내문을 표시한다.
- **BR-PLACE-14** 한국관광공사 원본 링크는 외부 브라우저로 이동한다.
- **BR-PLACE-15** 이미지가 없거나 로드에 실패하면 기본 이미지를 표시한다.

### 4.4 지도·관심 장소

- **BR-MAP-01** 최초 지도 중심은 현재 위치이며 기본 조회 반경은 3km다.
- **BR-MAP-02** 위치를 얻지 못하거나 해외에 있으면 기획된 기본 좌표를 사용한다. V3 후보는 카카오 판교 아지트다.
- **BR-MAP-03** 카카오맵 기준 기본 줌은 16~17, 지원 범위는 6~21이다.
- **BR-MAP-04** 북쪽 0도, 기울기 없음, 일반 지도 타입을 기본으로 한다.
- **BR-MAP-05** 마커 색은 문화유산·행사/축제·명소별로 일관되게 사용한다.
- **BR-MAP-06** 겹치는 마커는 클러스터링하며 1~9는 실제 개수, 10개 이상은 `9+`로 표시한다.
- **BR-MAP-07** 클러스터 선택 시 장소가 구분되는 줌 레벨로 이동한다.
- **BR-MAP-08** 위치 권한 거부, 위치 조회 시간 초과, 지도 SDK 실패를 구분한다.
- **BR-MAP-09** 관심 장소는 `(memberId, placeId)`당 하나만 존재해야 한다.
- **BR-MAP-10** 관심 등록/해제 재요청은 중복 상태를 만들지 않아야 한다.
- **BR-MAP-11** 관심 변경 실패 시 UI를 원래 상태로 복원한다.
- **BR-MAP-12** 선택한 가이드북의 일정 핀은 ScheduleItem의 핀 메타정보를 사용한다.
- **BR-MAP-13** 종료된 행사 등 표시 불가능 항목은 원본 일정에서 삭제하지 않고 지도 핀에서만 제외한다.

### 4.5 여행 조건·가이드북 생성

- **BR-GUIDE-01** 여행 시작일은 종료일보다 늦을 수 없다.
- **BR-GUIDE-02** 여행 일수는 시작일과 종료일을 모두 포함해 계산한다.
- **BR-GUIDE-03** 당일 여행은 `당일`, 복수 일자는 `n박 m일`로 표시한다.
- **BR-GUIDE-04** 동행 유형은 혼자, 친구, 연인, 가족, 단체 중 하나다.
- **BR-GUIDE-05** 동행 유형이 혼자이면 인원은 1명으로 고정한다.
- **BR-GUIDE-06** 지역과 기간이 유효해야 생성 요청 버튼을 활성화한다.
- **BR-GUIDE-07** 남은 생성 가능 횟수가 0이면 생성 요청을 거절한다.
- **BR-GUIDE-08** 중복 클릭·네트워크 재시도는 하나의 GenerationJob만 생성해야 한다.
- **BR-GUIDE-09** 생성 단계는 `취향에 맞는 장소 찾기`, `기간 중 행사 확인`, `일정 짜기` 순서다.
- **BR-GUIDE-10** 생성 작업은 앱 종료와 무관하게 서버에서 계속 진행한다.
- **BR-GUIDE-11** 앱 재진입 시 MAP-01을 표시하되 생성 상태를 다시 조회할 수 있어야 한다.
- **BR-GUIDE-12** 성공·실패·재시도 결과는 동일 jobId에 연결한다.
- **BR-GUIDE-13** 생성 완료 전 불완전한 가이드북을 정상 목록에 노출하지 않는다.

### 4.6 가이드북·일정 관리

- **BR-SCHEDULE-01** 가이드북은 한 명의 소유 회원을 가진다.
- **BR-SCHEDULE-02** 소유자 또는 공유로 사본을 받은 현재 소유자만 조회·관리할 수 있다.
- **BR-SCHEDULE-03** 가이드북에는 제목, 여행 기간, 동행, 인원, 취향 스냅샷, 썸네일, Day별 일정이 포함된다.
- **BR-SCHEDULE-04** 제목은 여행 지역명을 기반으로 만들고 같은 제목·일정이면 `(1)`, `(2)`로 구분한다.
- **BR-SCHEDULE-05** 목록은 여행 시작일 오름차순, 시작일이 같으면 생성일 내림차순이다.
- **BR-SCHEDULE-06** 사용자 임의 정렬 변경은 V3에서 제공하지 않는다.
- **BR-SCHEDULE-07** 목록은 무한 스크롤하며 안정된 커서 기준으로 중복·누락을 방지한다.
- **BR-SCHEDULE-08** 취향은 카드에 최대 2개, 초과분은 `+n`으로 표시한다.
- **BR-SCHEDULE-09** Day 내부 방문 순서는 중복되지 않는 양의 정수다.
- **BR-SCHEDULE-10** 일정 요약은 첫 장소와 나머지 수를 표시하며 한 곳이면 `외 n곳`을 표시하지 않는다.
- **BR-SCHEDULE-11** 외부 장소가 변경·삭제돼도 기존 일정 순서와 스냅샷 표시값을 복구할 수 있어야 한다.
- **BR-SCHEDULE-12** 삭제는 재확인 후 실행하며 성공 전 영구 제거하지 않는다.

### 4.7 가이드북 공유

- **BR-SHARE-01** 공유 방식은 앱 사용자 공유와 파일 링크 공유다.
- **BR-SHARE-02** 앱 공유 링크는 발급 시점부터 24시간 유효하다.
- **BR-SHARE-03** 만료·취소·존재하지 않는 링크는 내용을 노출하지 않는다.
- **BR-SHARE-04** 앱 미설치 사용자는 설치 페이지로 안내한다.
- **BR-SHARE-05** 미로그인 사용자는 AUTH-01로 이동하고 로그인 후 원래 공유 흐름으로 복귀한다.
- **BR-SHARE-06** 수신자는 요약 확인 후 명시적으로 `내 가이드북에 추가`해야 한다.
- **BR-SHARE-07** 동일 수신자가 동일 공유 원본을 반복 추가해도 사본은 한 개만 생성한다.
- **BR-SHARE-08** 가져오기는 가이드북, Day, 일정 항목, 핀 메타정보를 하나의 처리 단위로 복제한다.
- **BR-SHARE-09** 일부만 복제되면 전체 롤백하거나 실패 상태로 복구한다.
- **BR-SHARE-10** 가져온 가이드북은 수신자 소유의 독립 사본으로 관리하는 것을 기본안으로 한다.
- **BR-SHARE-11** 개인 메모·알림 상태·평가·계정 정보는 사본에 포함하지 않는다.
- **BR-SHARE-12** 파일 공유 결과물의 형식과 개인정보 범위는 별도 확정한다.

### 4.8 여행 종료 평가

- **BR-REVIEW-01** 일정 종료일 이후 첫 앱 접속 시 미처리 평가 안내를 최대 한 번 자동 노출한다.
- **BR-REVIEW-02** 평가 대상은 일정에 포함된 장소이며 방문 순서대로 제시한다.
- **BR-REVIEW-03** 사용자는 이전·다음으로 제출 전 별점을 수정할 수 있다.
- **BR-REVIEW-04** 개별 장소 평가를 건너뛸 수 있다.
- **BR-REVIEW-05** 마지막 장소에서는 `다음` 대신 `제출하기`를 제공한다.
- **BR-REVIEW-06** 제출 성공 후 완료 토스트를 표시한다.
- **BR-REVIEW-07** 최초 안내에서 전체 평가를 건너뛰면 자동 모달을 재노출하지 않는다.
- **BR-REVIEW-08** 이후 GUIDE-01의 평가 문구로 수동 진입할 수 있다.
- **BR-REVIEW-09** 모달 X와 전체 평가 건너뛰기를 동일 처리할지는 확정이 필요하다.
- **BR-REVIEW-10** 같은 회원·일정 항목에 유효 평점은 하나만 존재해야 한다.
- **BR-REVIEW-11** 제출 재시도는 평점을 중복 생성하지 않아야 한다.
- **BR-REVIEW-12** 일부 장소만 저장되지 않도록 세션 단위 원자 처리 또는 항목별 멱등 저장 후 최종 완료 처리가 필요하다.
- **BR-REVIEW-13** 평점 범위와 0.5점 허용 여부는 프론트·백엔드가 동일하게 확정한다.

### 4.9 장소 랭킹

- **BR-RANK-01** 랭킹 대상은 제출 완료된 장소 평가다.
- **BR-RANK-02** 월간은 해당 월, 주간은 해당 주에 방문한 평가를 집계한다.
- **BR-RANK-03** 주간 경계는 Asia/Seoul 기준 월요일 00:00부터 일요일 23:59:59까지다.
- **BR-RANK-04** 평가 작성일이 아니라 일정의 방문일을 집계 기간 판단에 사용한다.
- **BR-RANK-05** 단순 평균이 아니라 베이지안 가중 평균을 사용한다.

```text
WR = (v / (v + m)) × R + (m / (v + m)) × C

WR: 랭킹 정렬용 보정 점수
R : 해당 장소의 평균 평점
v : 해당 장소의 유효 평가 수
C : 같은 기간·지역 집계 모집단의 전체 평균 평점
m : 평가 수가 적은 장소를 보정하는 기준 평가 수
```

- **BR-RANK-06** 평가 수가 적으면 전체 평균 C에, 많으면 실제 평균 R에 가깝게 반영한다.
- **BR-RANK-07** `m`은 코드 상수가 아니라 운영 설정값으로 관리하고 실제 평가 분포로 결정한다.
- **BR-RANK-08** 정렬은 WR 내림차순, 평가 수 내림차순, 실제 평균 내림차순, placeId 오름차순이다.
- **BR-RANK-09** 화면에는 WR이 아니라 실제 평균 평점과 평가 수를 표시한다.
- **BR-RANK-10** 지역 선택 시 해당 지역 모집단에서 순위를 다시 계산한다.
- **BR-RANK-11** 랭킹 검색은 항목만 필터링하며 순위를 1위부터 다시 매기지 않는다.
- **BR-RANK-12** 평가 데이터 부족과 검색 결과 없음을 서로 다른 상태로 안내한다.
- **BR-RANK-13** 평가 수정·삭제 시 랭킹 재계산 또는 캐시 무효화가 보장돼야 한다.

### 4.10 알림·마이페이지

- **BR-NOTI-01** 인앱 알림은 계정별로 저장하고 읽음 여부를 관리한다.
- **BR-NOTI-02** 최초 진입 시 읽지 않은 알림을 최신순 최대 4개 노출한다.
- **BR-NOTI-03** 전체 보관 개수는 최대 20개이며 초과 삭제 기준을 확정해야 한다.
- **BR-NOTI-04** 알림 선택 시 읽음 처리 후 유형에 맞는 상세로 이동한다.
- **BR-NOTI-05** 대상 가이드북·행사가 삭제된 경우 안전한 대체 화면을 제공한다.
- **BR-NOTI-06** 모두 읽음은 읽지 않은 알림이 하나 이상일 때만 활성화한다.
- **BR-NOTI-07** 모두 읽음 실패 시 기존 목록을 유지한다.
- **BR-NOTI-08** 푸시 설정은 계정 단위로 저장한다.
- **BR-NOTI-09** 푸시 비활성화 상태에서도 인앱 알림과 토스트는 표시한다.
- **BR-MY-01** 마이페이지는 프로필, 가이드북 요약, 취향, 설정 메뉴를 조합한다.
- **BR-MY-02** 취향 수정 실패 시 기존 값을 유지한다.
- **BR-MY-03** 메뉴 이동 실패 시 현재 화면과 상태를 유지한다.

## 9. 프론트엔드 협의 항목

### 공통

- 날짜/시각 형식과 시간대, 오류 코드와 사용자 문구 매핑
- 로딩·빈 상태·오류·재시도 컴포넌트의 공통 규칙
- 상세 복귀 시 검색어·필터·페이지·스크롤 복원 범위
- 버튼 비활성화 시점과 실패 시 재활성화 시점

### 로그인·취향

- OAuth 취소와 실패 UI 구분
- 취향 최소·최대 선택 수와 세부 선택 종속 규칙
- 최초 설정 중 앱 종료 시 임시 선택 복원 여부
- 기본 취향과 여행별 취향을 구분하는 안내

### 지도·정보

- 위치 권한 거부 후 재요청 시점과 기본 좌표 안내
- 지도 이동 API debounce와 이전 요청 취소
- 클러스터/개별 핀 선택 동작
- 월 필터를 문화유산·명소에도 적용할지
- 랭킹 진입/복귀 시 일반 목록 상태 보존
- 원래 순위 유지 표현과 평가 부족 빈 상태

### 가이드북·공유

- 생성 중 앱 재진입 시 진행 상태 표시 위치
- 외부 데이터 일부 실패 시 부분 결과 허용 여부
- 로그인 후 공유 수신 화면으로 복귀하는 딥링크 규칙
- 중복 추가 응답과 안내 화면
- 파일 공유 형식, 생성 상태, 실패 재시도

### 평가·랭킹

- 평점 범위, 0.5점 허용, 미선택 상태
- 모달 X와 전체 `건너뛰기`의 의미 차이
- 평가 중 앱 종료 시 임시 저장 여부
- 제출 후 수정 가능 여부
- 장소 0개/모두 건너뜀 시 제출 상태
- 랭킹 집계 갱신 시각 표시 여부

### 알림·계정

- 알림 선택과 읽음 처리 순서
- 모두 읽음 실패 시 롤백 범위

## 12. 문서 간 일관성 규칙

- 화면의 문화유산·행사·명소는 ERD에서 공통 `Place`와 `Category`로 표현한다.
- 여행 조건은 입력, 가이드북은 결과 묶음, 일정은 Day와 방문 순서다. 세 용어를 혼용하지 않는다.
- 평가 세션과 장소 평가를 구분한다.
- 공유 링크, 공유 수신, 가이드북 사본을 하나의 상태로 합치지 않는다.
- API·ERD·테크스펙은 본 문서의 요구사항 ID를 연결한다.
- 상태 enum은 영문 고정 코드로 관리하고 화면 문구는 프론트에서 매핑한다.
- 시간 필드는 UTC instant인지 Asia/Seoul 날짜인지 명시한다.
- 외부 TourAPI ID와 내부 placeId를 동일 값으로 가정하지 않는다.

- 인앱 알림과 푸시 설정
- 24시간 공유 링크, 로그인 복귀, 중복 없는 사본 생성
- 여행 종료 평가와 월간·주간 베이지안 랭킹

### 단순화 가능

- 랭킹은 최초에 실시간 계산보다 정기 집계로 시작할 수 있다.
- 파일 공유가 부담되면 앱 링크 공유를 우선 구현한다.
- 공유 사본은 실시간 동기화 없이 스냅샷 복제로 제한한다.
- 텍스트 리뷰는 V3에 없으므로 구현하지 않는다.
- 개인화는 버전이 명시된 규칙 기반 가중치로 시작할 수 있다.

# KeepGo 도메인 사전

## 작성 기준

- 본 사전은 현재까지 합의된 요구사항과 도메인 분석 결과를 기준으로 작성한다.
- 한글 명칭은 기획, 개발 및 의사소통에서 사용하는 표준 용어로 간주한다.
- 영어 명칭은 코드 및 API 명칭을 정할 때 참고할 수 있는 권장 명칭이다.
- 표현 형식은 일자, 시간, 좌표, 범위 등 실제 표준화가 필요한 값에만 기재한다.
- 상태, 유형, 카테고리 및 역할의 구체 코드값은 본 사전에 열거하지 않는다.
- 별도의 표현 규칙이 필요하지 않은 용어는 표현 형식을 `—`로 표시한다.
- 값이 정해지지 않았거나 알 수 없는 경우 빈 문자열 대신 `null`을 사용한다.

## 공통 값 개념

여러 도메인 개념에서 반복하여 사용하는 일자와 시간 관련 용어를 다음과 같이 정의한다.

| 한글 명칭 | 영어 명칭 | 정의 | 표현 형식 |
|---|---|---|---|
| 일자 | Date | 연·월·일로 표현하며 시각과 시간대 정보를 포함하지 않는 달력상의 하루 | ISO 8601 `yyyy-MM-dd` (예: `2026-09-01`) |
| 시각 | Time | 특정 일자와 결합되지 않은 하루 중의 시간 | 24시간제 `HH:mm` (예: `14:30`) |
| 일시 | Date Time | 특정 일자의 특정 시점을 나타내며 시간대 정보를 포함하는 값 | ISO 8601 `yyyy-MM-dd'T'HH:mm:ssXXX` (예: `2026-09-01T14:30:00+09:00`) |
| 일자 범위 | Date Range | 시작일부터 종료일까지의 연속된 일자 범위. 시작일과 종료일을 모두 포함한다 | `시작일/종료일` (예: `2026-09-01/2026-09-10`) |
| 시간 범위 | Time Range | 하루 안에서 시작 시각부터 종료 시각까지의 범위 | `HH:mm-HH:mm` (예: `14:00-18:00`) |
| 소요 시간 | Duration | 두 시점 사이에 경과하거나 활동에 사용할 수 있는 시간의 양 | 0 이상의 분 단위 정수 (예: 2시간 30분은 `150`) |
| 시간대 | Time Zone | 일시 해석에 적용되는 지역별 표준 시간 기준 | IANA 시간대 식별자 권장 (예: `Asia/Seoul`) |

## 도메인 용어

| 한글 명칭 | 영어 명칭 | 정의 | 표현 형식 |
|---|---|---|---|
| 사용자 | User | 서비스에 로그인하여 콘텐츠를 저장하고 코스를 추천받으며 일정과 보관함을 관리하는 사람 | — |

| 닉네임 | Nickname | 서비스에서 사용자를 표시하는 이름 | 1~10자; 세부 허용 문자 정책은 비즈니스 규칙에서 정의 |
| 이메일 | Email Address | 사용자 계정에 연결되어 사용자를 식별하거나 연락에 사용하는 이메일 주소 | 이메일 주소 형식 |
| 연령대 | Age Range | 사용자 프로필에서 연령을 일정한 구간으로 나타낸 정보 | — |

| 외부 계정 연동 | External Account Connection | 사용자 계정과 외부 서비스 계정의 연결로, 해당 서비스의 원본 콘텐츠를 동기화하는 기준이 되는 관계 | — |
| 콘텐츠 동기화 | Content Synchronization | 연결된 외부 계정에서 원본 콘텐츠 목록을 가져와 서비스의 분석 대상으로 반영하는 작업 | — |
| 동기화 상태 | Synchronization Status | 콘텐츠 동기화 작업의 현재 처리 상태 | — |
| 마지막 동기화 일시 | Last Synchronized At | 외부 계정의 콘텐츠 동기화가 가장 최근에 완료된 시점 | 일시 또는 완료 이력이 없으면 `null` |
| 원본 콘텐츠 | Source Content | 장소 또는 이벤트 정보를 발견하고 추출하는 근거가 되는 SNS 영상, URL 또는 이미지 | — |
| 콘텐츠 플랫폼 | Content Platform | 원본 콘텐츠가 게시되거나 제공되는 외부 서비스 | — |
| 콘텐츠 유형 | Content Type | 원본 콘텐츠의 플랫폼과 구분되는 영상, 게시물 또는 이미지 등의 매체 형식 | — |
| 원본 콘텐츠 URL | Source Content URL | 원본 콘텐츠에 접근하기 위한 주소 | URI/URL 문자열 |
| 콘텐츠 분석 | Content Analysis | 원본 콘텐츠에서 장소명, 이벤트명, 지역, 기간, 카테고리 등의 정보를 구조화하는 과정 | — |
| 콘텐츠 분석 작업 | Content Analysis Job | 하나 이상의 원본 콘텐츠를 묶어 분석을 실행하고 처리 상태와 완료 결과를 관리하는 단위 | — |
| 콘텐츠 분석 항목 | Content Analysis Item | 하나의 원본 콘텐츠에서 추출된 개별 장소 또는 이벤트 후보와 그 분석 정보를 나타내는 항목 | — |

| 이벤트 후보 | Event Candidate | 원본 콘텐츠에서 추출됐지만 사용자 확인 또는 검증이 끝나지 않은 이벤트 | — |

| 운영 시간 | Operating Hours | 장소 또는 이벤트 개최를 이용할 수 있는 요일별 시간 범위 | 요일 + 시간 범위 (예: `MON 10:00-20:00`) |
| 이벤트 개최 상태 | Event Occurrence Status | 현재 일자와 개최 기간을 기준으로 계산한 이벤트 개최의 진행 상태 | — |

| 카테고리 | Category | 장소 또는 이벤트의 성격을 구분하는 분류 | — |

| 알림 설정 | Notification Preference | 사용자와 알림 유형 사이의 수신 설정. 전체 알림 설정은 유형별 설정에 우선하여 적용한다 | Boolean: `true`, `false` |
| 장소 랭킹 | Place Ranking | 인기 지표를 기준으로 장소를 순서화한 탐색 정보 | 순위: 1 이상의 정수 |
| 인기 지표 | Popularity Metric | SNS 언급량, 저장 횟수, 최근 인기 추이 및 산정 기준 시점 등을 바탕으로 장소의 인기를 판단하는 근거 | — |

## 해석상 유의사항

- `이벤트`는 행사 자체이고, `이벤트 개최`는 해당 이벤트가 특정 장소와 기간에 열리는 회차이다.
- 보관함에서 이벤트를 저장한다는 표현은 도메인상 특정 `이벤트 개최`를 저장한다는 의미로 사용한다.
- `지난 이벤트`는 독립적인 저장 대상이 아니라 종료된 이벤트 개최를 조회하기 위한 분류이다.
- `코스 후보`는 추천 과정에서 생성된 선택지이며, 사용자가 선택해 저장한 결과를 `외출 코스`라고 한다.
- `외출 코스`는 재사용 가능한 방문 경로와 이동 계획이고, `일정`은 외출 코스를 특정 일자와 시간에 실행하기 위한 계획이다.
- 추천 과정에서 입력된 일자와 시간은 코스 산정을 위한 기준값이다. 일정 생성 시 초기값으로 사용할 수 있지만 일정의 일자와 시간은 별도로 관리한다.
- `마지막 동기화 일시`, `최초 저장 일시`, `저장 일시`, `삭제 일시`, `예상 도착 일시`, `일정 시작 일시`, `일정 종료 일시`, `알림 확인 일시`에서 사용하는 `일시`는 공통 값 개념에 정의된 시간대 포함 ISO 8601 형식을 따른다.

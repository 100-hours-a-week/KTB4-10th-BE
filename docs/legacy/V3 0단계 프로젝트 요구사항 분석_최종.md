# KulInOne V3 0단계 프로젝트 요구사항 분석

> 기준 화면: Figma `10팀_Figma` → `화면설계서` → `V3` (`12495:8705`)  
> 기준일: 2026-08-31  
> 문서 상태: ERD·API·기술 선정·테크스펙 착수 전 팀 리뷰 초안

## 1. 문서 목적

이 문서는 V3 화면설계서와 기능정의서를 개발 가능한 요구사항 단위로 정리한 0단계 기준 문서다. 도메인 용어와 경계를 정의하고 비즈니스 규칙·기능 요구사항·비기능 요구사항·예외 시나리오를 요구사항 ID로 추적할 수 있게 하는 것이 목적이다.

본 문서에서 사용하는 상태는 다음과 같다.

- **확정(V3)**: 현재 Figma 기능정의서에 명시됨
- **설계 권장안**: 구현 가능성과 데이터 정합성을 고려한 후속 설계의 기본값
- **리뷰 필요**: V3 내부에서 규칙이 충돌하거나 현재 기준만으로 결론을 확정할 수 없음

## 2. 문서 작성 기준

- 기준 범위는 현재 Figma `V3` 프레임 내부의 화면설계서와 기능정의서다.
- 도메인은 화면명이 아니라 고유한 비즈니스 규칙과 데이터 생명주기를 기준으로 나눈다.
- 사용자에게 보이는 문구와 시스템 내부 상태를 구분한다.
- 외부 관광 데이터 식별자와 KulInOne 내부 식별자를 구분한다.
- 요구사항에서 결정된 정책과 추가 논의가 필요한 내용을 명시적으로 구분한다.
- 화면설계서, ERD, API, 코드에서 같은 용어와 상태명을 사용한다.

## 3. 서비스 범위와 외부 연동

KulInOne은 사용자의 소셜 로그인 정보, 여행 취향, 여행 조건을 바탕으로 주변 관광 정보를 제공하고 AI 맞춤 가이드북을 생성·저장·공유하는 서비스다.

| 외부 시스템 | 목적 | 소유 도메인 |
|---|---|---|
| 카카오·구글 OAuth | 회원 인증과 외부 계정 식별 | DOM-01 |
| 카카오 지도 | 위치·지도·마커·클러스터 표현 | DOM-04 |
| TourAPI 등 관광 데이터 | 장소·행사·이미지·출처 데이터 | DOM-03 |
| LLM/추천 엔진 | 지역 추천, 일정·가이드북 생성과 수정 | DOM-05 |
| 외부 PG | 생성권 결제·환불 | DOM-08 |
| APNs/FCM | 푸시 알림 전송 | DOM-07 |
| OS 파일·공유 기능 | PDF 저장, 링크/파일 공유 | DOM-05-S |

### 4.1 도메인 관계

| 주체 | 관계 | 대상 | 설명 |
|---|---|---|---|
| 회원 | 1:1 | 기본 취향 프로필 | 현재 적용되는 기본 취향을 가진다. |
| 회원 | 1:N | 가이드북 | 여러 가이드북을 소유한다. |
| 회원 | N:M | 관광 콘텐츠 | 관심 장소 관계로 연결된다. |
| 가이드북 생성 요청 | N:1 | 취향 스냅샷 | 생성 당시 적용된 취향을 보존한다. |
| 가이드북 | 1:N | 일차 | 여행 일수만큼 일차를 가진다. |
| 일차 | 1:N | 일정 항목 | 방문 순서가 있는 항목을 가진다. |
| 일정 항목 | N:1 | 관광 콘텐츠 | 장소 또는 행사 개최 정보를 참조한다. |
| 가이드북 | 1:N | 공유 링크 | 링크별 만료·폐기 상태를 가진다. |
| 공유 링크 | 1:N | 가져오기 기록 | 여러 회원이 유효한 링크를 사용할 수 있다. |
| 회원+가이드북 | 1:1 | 평가 세션 | 한 여행의 평가 진행 단위다. |
| 평가 세션 | 1:N | 장소 별점/건너뛰기 | 일정 항목별 결과를 가진다. |
| 회원 | 1:N | 알림 | 수신 회원별 읽음 상태를 가진다. |
| 회원 | 1:N | 생성권 원장 | 무료 지급·구매·차감·환불 이력을 가진다. |
| 주문 | 1:N | 결제 시도 | 실패 후 재시도와 PG 콜백을 추적한다. |

## 5. 용어 사전

### 5.1 공통 값

| 용어 | 영문명 | 기준 |
|---|---|---|
| 식별자 | Identifier | 외부에 의미 없는 내부 ID 사용 |
| 날짜 | Date | `YYYY-MM-DD` |
| 일시 | DateTime | ISO 8601, 저장 UTC, 표시 시 지역 시간대 적용 |
| 날짜 범위 | DateRange | `{startDate, endDate}`, 양 끝 포함 |
| 시간대 | TimeZone | 국내 정책 기본 `Asia/Seoul` |
| 지역 코드 | RegionCode | 행정구역 표준 코드, 화면은 명칭 표시 |
| 좌표 | Coordinates | `{latitude, longitude}` |
| 지도 범위 | MapViewport | 중심, 줌, 경계 좌표 |
| 거리 | Distance | 미터 저장, 화면에서 m/km 변환 |
| 별점 | RatingValue | 0~5 정수. 0점의 유효 평가 포함 여부는 구현 전 확인 |
| 만료 일시 | ExpiresAt | 링크·임시 자원이 무효가 되는 시점 |

## 7. 비즈니스 규칙

### 7.1 회원·취향

| ID | 규칙 | 상태 |
|---|---|---|
| BR-AUTH-01 | 카카오·구글 OAuth만 제공하고 제공자 계정은 한 회원에 한 번만 연결한다. | 확정+설계 권장 |
| BR-AUTH-02 | OAuth 처리 중 모든 로그인 버튼을 비활성화하고 중복 회원 생성을 막는다. | 확정(V3) |
| BR-AUTH-03 | 기존 회원은 MAP-01, 신규 또는 취향 미완료 회원은 PREF-01로 이동한다. | 확정(V3) |
| BR-PREF-01 | PREF-01 대분류는 최소 1개, 최대 3개다. | 확정(V3) |
| BR-PREF-02 | 대분류 해제 시 종속 중분류를 함께 해제한다. | 확정(V3) |
| BR-PREF-03 | 공통 여행 스타일은 대분류와 무관하고 선택 수 제한이 없다. | 확정(V3) |
| BR-PREF-04 | 가이드북 최초 생성은 회원의 기본 취향만 사용하며 별도의 추가 취향 입력은 받지 않는다. 생성 당시 기본 취향은 스냅샷으로 보존한다. | 결정 |
| BR-PREF-05 | 재생성 시 자연어 수정 요청을 반영할 수 있으나 해당 가이드북에만 적용하고 회원 기본 취향은 변경하지 않는다. | 결정 |

### 7.2 관광 콘텐츠·탐색·지도

| ID | 규칙 | 상태 |
|---|---|---|
| BR-CONTENT-01 | 외부 콘텐츠 ID는 내부 ID를 대체하지 않으며 `source+externalId`로 유일하다. | 설계 권장안 |
| BR-CONTENT-02 | 행사의 종료일은 시작일보다 빠를 수 없다. | 설계 권장안 |
| BR-MAP-01 | 위치 권한이 있으면 현 위치 반경 3km의 콘텐츠를 조회한다. | 확정(V3) |
| BR-MAP-02 | 지도 카테고리는 문화유산·행사/축제·명소이며 기본은 행사/축제다. | 확정(V3) |
| BR-MAP-03 | 클러스터는 1~9를 숫자, 10 이상을 `9+`로 표시한다. | 확정(V3) |
| BR-MAP-04 | 관심 장소는 `memberId+contentId`로 유일하며 등록·해제는 멱등하다. | 설계 권장안 |
| BR-INFO-01 | 검색어는 최대 10자, Enter 제출 방식이며 검색어와 필터는 AND 조건이다. | 확정(V3) |
| BR-INFO-02 | 행사 상태는 시작일 00:00, 종료일 23:59와 서버 시간대를 기준으로 계산한다. | 확정(V3) |
| BR-INFO-03 | INFO-02에서 목록 복귀 시 검색·필터·스크롤 상태를 복원한다. | 확정(V3) |
| BR-RANK-01 | 랭킹은 제출된 유효 별점만 사용하며 별점 작성일을 기준으로 일·주·월 단위 집계한다. | 결정 |
| BR-RANK-02 | 랭킹 기간은 일·주·월이며 베이지안 보정 점수 내림차순, 동점은 평가 수 내림차순이다. | 확정(V3) |

### 7.3 가이드북·공유·평가

| ID | 규칙 | 상태 |
|---|---|---|

## 10. 상태 모델 권장안

### 10.1 회원

- `AccountStatus`: `ACTIVE → WITHDRAWAL_PENDING → WITHDRAWN`
- `OnboardingStatus`: `PREFERENCE_REQUIRED → COMPLETED`
- OAuth 실패·취소는 회원 상태를 만들거나 바꾸지 않는다.

### 10.2 가이드북 생성 작업

`QUEUED → RUNNING(FIND_PLACES → CHECK_EVENTS → BUILD_ITINERARY) → SUCCEEDED | FAILED | CANCELLED`

- 완료 단계는 뒤로 가지 않는다.
- 각 최초 생성 또는 재생성 작업의 최초 `SUCCEEDED` 전환에서 가이드북을 저장하고 생성권 1회를 차감한 뒤 GUIDE-05 진입이 가능해진다.
- 실패 코드는 `NETWORK`, `TIMEOUT`, `UPSTREAM`, `SERVER`, `VALIDATION`, `QUOTA`를 최소 후보로 한다.

### 10.3 평가 세션

`NOT_STARTED → IN_PROGRESS → SUBMITTED | DISMISSED`

- 장소별 `SKIPPED`는 세션 전체의 `DISMISSED`와 구분한다.
- `SUBMITTED`는 최종 상태이며 제출 후 별점을 수정할 수 없다.

### 10.4 공유 링크

`ACTIVE → EXPIRED | REVOKED`

- 만료·폐기 상태에서는 미리보기와 가져오기를 거부한다.

### 10.5 주문·결제

`CREATED → PAYMENT_PENDING → PAID → FULFILLED`

실패/취소/환불: `CANCELLED | FAILED | REFUND_PENDING → REFUNDED`

- `PAID`는 PG 서버 검증 후에만 가능하다.
- `FULFILLED`는 생성권 지급 완료이며 중복 콜백으로 재지급하지 않는다.

## 16. 셀프 리뷰

- **요구사항 연결**: 도메인, 사용자 시나리오, 비즈니스 규칙, 기능·비기능 요구사항, 화면과 후속 설계를 연결했다.
- **설계 근거**: 원본/조회 모델 분리, 비동기 생성, 원장형 생성권, 서버 결제 검증의 이유를 명시했다.
- **대안·트레이드오프**: 확정 정책과 추가 논의가 필요한 정책을 구분했다.
- **정상·예외 시나리오**: 인증, 권한, 생성, 공유, 평가, 결제, 탈퇴의 실패·중복·경계값을 포함했다.
- **문서 일관성**: 용어, 상태, 화면 ID, 데이터 소유권 차이를 `REV`, `GAP`로 추적한다.
- **구현 가능성**: P0/P1 우선순위와 구현 전 P0 결정사항을 분리했다.

# KeepGo 비즈니스 규칙

## 작성 기준

- 각 규칙은 조건에 따라 허용·금지되는 행위 또는 반드시 유지해야 하는 결과를 정의한다.
- 동일한 요청이나 외부 처리 결과가 반복되어도 결과가 달라지지 않아야 하는 경우 멱등성 규칙을 명시한다.
- 상태, 유형, 카테고리 및 역할의 구체 코드값은 이 문서에서 정의하지 않는다.
- 화면 배치, 스크롤, 로딩 표시, 페이지 크기와 같은 UI 동작은 제외한다.
- 현재 명세로 결정할 수 없는 사항은 `정책 결정 필요 사항`에 분리한다.

## 1. 사용자와 외부 계정

### BR-USER-001 개인 보관함 유일성

한 사용자는 개인 보관함을 정확히 하나만 가져야 한다.

### BR-USER-002 외부 계정 기반 사용자 유일성

동일한 외부 서비스의 동일 계정 식별자로 로그인이 반복되어도 사용자 계정은 하나만 존재해야 한다.

### BR-USER-003 최초 로그인 처리

외부 계정에 대응하는 사용자 계정이 없을 때만 새 사용자 계정과 개인 보관함을 생성해야 한다.

### BR-USER-004 프로필 이름 길이

사용자의 닉네임은 1자 이상 10자 이하여야 한다.

### BR-ACCOUNT-001 연동 해제의 영향

외부 계정 연동을 해제해도 이미 생성된 원본 콘텐츠, 분석 결과, 장소, 이벤트, 이벤트 개최, 외출 코스와 저장 관계를 삭제해서는 안 된다.

## 2. 콘텐츠 동기화

### BR-SYNC-001 동기화 실행 조건

유효한 외부 계정 연동이 없는 계정에 대해서는 콘텐츠 동기화를 시작해서는 안 된다.

### BR-SYNC-002 원본 콘텐츠 유일성

동일한 외부 콘텐츠가 여러 동기화 작업에서 반복 전달되어도 원본 콘텐츠는 하나만 존재해야 한다.

### BR-SYNC-003 동기화 결과 멱등성

동일한 동기화 결과가 여러 번 전달되어도 새 원본 콘텐츠와 분석 대상은 중복 생성되어서는 안 된다.

### BR-SYNC-004 마지막 동기화 일시

동기화가 정상적으로 완료된 경우에만 마지막 동기화 일시를 갱신해야 하며, 실패한 동기화는 기존 값을 변경해서는 안 된다.

### BR-SYNC-005 동시 동기화

동일한 외부 계정 연동에 대해 둘 이상의 동기화 작업이 동시에 실행되어서는 안 된다.

## 3. 콘텐츠 분석

### BR-ANALYSIS-001 분석 작업 대상

하나의 콘텐츠 분석 작업은 하나 이상의 원본 콘텐츠를 포함해야 하며, 각 원본 콘텐츠는 작업 안에서 한 번만 처리 대상이 되어야 한다.

### BR-ANALYSIS-002 복수 대상 추출

한 원본 콘텐츠에서 여러 장소와 이벤트가 추출되면 각 대상을 독립된 분석 항목으로 관리해야 한다.

### BR-ANALYSIS-003 부분 실패 격리

한 원본 콘텐츠의 분석이 실패해도 같은 분석 작업의 나머지 원본 콘텐츠 처리를 중단해서는 안 된다.

### BR-ANALYSIS-004 분석 작업 완료 조건

분석 작업에 포함된 모든 원본 콘텐츠가 성공, 실패 또는 미분석 중 하나의 최종 처리 결과를 가져야만 분석 작업을 완료할 수 있다.

### BR-ANALYSIS-005 분석 완료 처리 멱등성

동일한 분석 작업의 완료 결과가 여러 번 전달되어도 작업 완료 처리는 한 번만 수행되어야 한다.

### BR-ANALYSIS-006 분석 결과 반영 멱등성

동일한 분석 결과가 여러 번 전달되어도 장소, 이벤트, 이벤트 개최와 원본 출처 관계가 중복 생성되어서는 안 된다.

### BR-ANALYSIS-007 후보 확정 전 분리

검증 또는 실제 장소 매칭이 끝나지 않은 장소 후보와 이벤트 후보를 확정된 장소·이벤트로 취급해서는 안 된다.

## 4. 장소, 이벤트와 원본 출처

### BR-PLACE-001 장소 중복 방지

외부 장소 식별자 등 동일성 기준이 일치하는 장소가 이미 존재하면 새 장소를 생성하지 않고 기존 장소를 사용해야 한다.

### BR-PLACE-002 지역 판정

장소의 지역은 장소 주소를 기준으로 시·도 단위에서 판정해야 한다.

### BR-EVENT-001 이벤트와 이벤트 개최 분리

동일한 행사가 장소 또는 기간을 달리하여 열리면 이벤트 공통 정보는 재사용하고 각 장소·기간의 이벤트 개최를 별도로 생성해야 한다.

### BR-EVENT-002 이벤트 개최 귀속

모든 이벤트 개최는 정확히 하나의 이벤트에 속해야 한다.

### BR-EVENT-003 이벤트 개최 중복 방지

동일한 이벤트가 동일한 장소에서 동일한 기간에 열리는 이벤트 개최는 중복 생성되어서는 안 된다.

### BR-EVENT-004 이벤트 저장 대상 제한

보관함에는 이벤트 자체를 저장해서는 안 되며 특정 이벤트 개최만 저장해야 한다.

### BR-EVENT-005 개최 상태 계산

이벤트 개최 상태는 서비스 기준 시간대의 현재 일자와 개최 시작일·종료일을 비교하여 계산해야 한다.

### BR-EVENT-006 지난 이벤트 분류

종료된 이벤트 개최만 지난 이벤트 조회 결과에 포함해야 하며, 지난 이벤트를 독립 객체나 별도 저장 관계로 생성해서는 안 된다.

### BR-SOURCE-001 원본 출처 유일성

동일한 원본 콘텐츠와 동일한 장소·이벤트·이벤트 개최 사이에는 원본 출처 관계가 하나만 존재해야 한다.

### BR-SOURCE-002 원본 접근 불가의 영향

원본 콘텐츠에 접근할 수 없게 되어도 이미 확정된 장소, 이벤트, 이벤트 개최와 저장 관계를 삭제해서는 안 된다.

## 5. 보관함과 저장

### BR-SAVE-001 활성 저장 관계 유일성

같은 보관함과 같은 대상 사이에는 활성 저장 관계가 최대 하나만 존재해야 한다.

### BR-SAVE-002 저장 요청 멱등성

이미 활성 상태로 저장된 대상을 같은 보관함에 다시 저장해도 새 저장 관계를 생성하거나 최초 저장 일시와 저장 일시를 변경해서는 안 된다.

### BR-SAVE-003 삭제 대상

보관함에서 대상을 삭제할 때 장소, 이벤트 개최 또는 외출 코스 자체를 삭제해서는 안 되며 저장 관계만 Soft Delete해야 한다.

### BR-SAVE-004 삭제 요청 멱등성

이미 삭제된 저장 관계에 삭제 요청이 반복되어도 삭제 일시를 다시 변경하거나 추가 삭제 처리를 수행해서는 안 된다.

### BR-SAVE-005 재저장

Soft Delete된 대상을 같은 보관함에 다시 저장하면 기존 저장 관계를 활성화하고, 최초 저장 일시는 유지하며 저장 일시만 현재 활성화 시점으로 갱신해야 한다.

### BR-SAVE-006 보관함 간 저장 독립성

한 보관함의 저장 관계를 생성·삭제·재활성화해도 다른 보관함의 저장 관계가 변경되어서는 안 된다.

### BR-SAVE-007 공유 보관함 복사

개인 보관함의 대상을 공유 보관함에 추가할 때 대상 객체를 복제해서는 안 되며 공유 보관함과 대상 사이에 별도 저장 관계를 생성해야 한다.

### BR-SAVE-008 공유 보관함 복사 멱등성

같은 대상을 같은 공유 보관함으로 여러 번 복사해도 활성 저장 관계는 하나만 존재해야 한다.

### BR-SAVE-009 지역 필터

장소는 자신의 지역으로, 이벤트 개최는 개최 장소의 지역으로 필터링해야 하며 지역을 판정할 수 없는 대상은 특정 지역의 결과에 포함해서는 안 된다.

## 6. 공유 보관함, 초대와 권한

### BR-SHARED-001 생성자 권한

공유 보관함을 생성한 사용자는 생성과 동시에 해당 보관함을 소유하는 참여자가 되어야 한다.

### BR-SHARED-002 참여 관계 유일성

같은 사용자와 같은 공유 보관함 사이에는 활성 참여 관계가 최대 하나만 존재해야 한다.

### BR-SHARED-003 초대 수락 멱등성

동일한 사용자가 같은 공유 보관함의 초대를 여러 번 수락해도 참여 관계를 중복 생성해서는 안 된다.

### BR-SHARED-004 유효하지 않은 초대

만료되거나 취소된 보관함 초대로는 새로운 참여 관계를 생성해서는 안 된다.

### BR-SHARED-005 권한 없는 변경 금지

해당 작업 권한이 없는 사용자는 공유 보관함의 이름, 참여자, 역할 또는 저장 항목을 변경해서는 안 된다.

### BR-SHARED-006 저장 데이터 독립성

공유 보관함의 저장 항목을 삭제해도 참여자의 개인 보관함 저장 관계가 변경되어서는 안 된다.

## 7. 추천 대화와 추천 요청

### BR-RECOMMEND-001 추천 필수 조건

지역, 추천 기준일, 추천 시간 범위, 이동 가능 시간과 카테고리가 모두 입력되기 전에는 코스 추천을 실행해서는 안 된다.

### BR-RECOMMEND-002 추천 후보 범위

추천 후보는 사용자의 보관함에 활성 상태로 저장된 장소와 이벤트 개최에서만 선별해야 한다.

### BR-RECOMMEND-003 코스 후보 수

하나의 추천 요청에서 코스 후보는 최대 3개까지만 생성해야 한다.

### BR-RECOMMEND-004 추천 결과 귀속

생성된 코스 후보는 정확히 하나의 추천 요청에 속해야 한다.

### BR-RECOMMEND-005 추천 완료 처리 멱등성

동일한 추천 요청의 결과가 여러 번 전달되어도 같은 코스 후보를 중복 생성해서는 안 된다.

### BR-RECOMMEND-006 대화 이력 귀속

모든 추천 대화 메시지는 정확히 하나의 추천 대화에 속해야 한다.

### BR-RECOMMEND-007 대화 초기화

사용자가 추천 대화를 초기화하면 기존 메시지를 삭제하거나 새 대화에 편입해서는 안 되며 새 추천 대화를 시작해야 한다.

## 8. 외출 코스와 일정

### BR-COURSE-001 코스 저장

사용자가 코스 후보를 저장하면 해당 후보의 방문지와 방문 순서를 사용하여 외출 코스를 생성하고 보관함과 외출 코스 사이에 저장 관계를 생성해야 한다.

### BR-COURSE-002 코스 저장 멱등성

동일한 추천 요청의 동일 코스 후보에 대한 저장 요청이 반복되어도 외출 코스와 저장 관계를 중복 생성해서는 안 된다.

### BR-COURSE-003 코스 방문지 순서

하나의 외출 코스 안에서 두 코스 방문지가 같은 방문 순서를 가져서는 안 된다.

### BR-COURSE-004 코스 스냅샷 불변성

외출 코스가 저장된 이후 참조하는 장소 또는 이벤트 개최의 정보가 변경되어도 코스 방문지에 보존된 표시 정보와 방문 순서를 자동으로 변경해서는 안 된다.

### BR-COURSE-005 참조 대상 접근 불가

코스 방문지가 참조하는 장소·이벤트 개최 또는 원본 콘텐츠에 접근할 수 없어도 외출 코스와 코스 방문지를 삭제해서는 안 된다.

### BR-COURSE-006 코스 삭제 영향

외출 코스의 저장 관계를 삭제해도 코스에 포함된 장소와 이벤트 개최를 삭제해서는 안 된다.

### BR-SCHEDULE-001 외출 코스와 일정 분리

추천 조건의 일자·시간 또는 외출 코스의 예상 시간 정보가 변경되어도 이미 생성된 일정의 실행 일자·시간을 자동으로 변경해서는 안 된다.

## 9. 알림

### BR-NOTIFICATION-001 전체 알림 설정 우선

전체 알림 설정이 비활성화된 사용자에게는 유형별 설정과 관계없이 새 알림을 제공해서는 안 된다.

### BR-NOTIFICATION-002 유형별 알림 설정

전체 알림 설정이 활성화된 경우에는 해당 알림 유형의 수신 설정이 활성화된 사용자에게만 새 알림을 제공해야 한다.

### BR-NOTIFICATION-003 알림 확인 멱등성

이미 확인한 알림을 다시 확인해도 최초 알림 확인 일시를 변경해서는 안 된다.

### BR-NOTIFICATION-004 시작 임박 알림

시작일을 알 수 있는 이벤트 개최에 대해 시작일 7일 전과 1일 전에 각각 한 번씩 시작 임박 알림을 생성해야 한다.

### BR-NOTIFICATION-005 종료 임박 알림

종료일을 알 수 있는 이벤트 개최에 대해 종료일 10일 전에 한 번만 종료 임박 알림을 생성해야 한다.

### BR-NOTIFICATION-006 이벤트 임박 알림 유일성

같은 사용자·이벤트 개최·알림 기준일·알림 목적에 해당하는 이벤트 임박 알림은 하나만 존재해야 한다.

### BR-NOTIFICATION-007 알림 소급 생성 금지

사용자가 알림 기준일이 지난 후 이벤트 개최를 저장하면 이미 지난 기준의 임박 알림을 소급 생성해서는 안 된다.

### BR-NOTIFICATION-008 종료일 없는 이벤트

종료일을 알 수 없는 이벤트 개최에는 종료 임박 알림을 생성해서는 안 된다.

### BR-NOTIFICATION-009 삭제된 저장 항목의 향후 알림

이벤트 개최의 저장 관계가 삭제된 이후에는 해당 사용자에게 아직 생성되지 않은 임박 알림을 새로 생성해서는 안 된다.

### BR-NOTIFICATION-010 분석 완료 알림

분석 작업의 모든 원본 콘텐츠가 최종 처리 결과를 가지면 해당 작업의 분석된 장소 수, 이벤트 수와 실패 또는 미분석 콘텐츠 수를 포함한 완료 알림을 생성해야 한다.

### BR-NOTIFICATION-011 분석 완료 알림 멱등성

동일한 분석 작업의 완료 처리가 반복되어도 분석 완료 알림은 하나만 생성되어야 한다.

## 10. 지도와 랭킹

### BR-MAP-001 지도 표시 조건

사용자의 보관함에 활성 상태로 저장된 장소와 이벤트 개최 중 유효한 좌표를 확인할 수 있는 대상만 지도에 표시해야 한다.

### BR-MAP-002 이벤트 개최 위치

이벤트 개최의 지도 위치와 지역은 연결된 개최 장소의 좌표와 지역을 사용해야 한다.

### BR-MAP-003 위치 미확정 대상

실제 장소와 매칭되지 않았거나 유효한 좌표가 없는 대상은 지도에 표시해서는 안 된다.

### BR-RANKING-001 랭킹 근거 일치

사용자에게 표시하는 인기 근거는 해당 장소의 랭킹 산정에 실제 사용된 인기 지표와 일치해야 한다.

## 정책 결정 필요 사항

다음 항목은 규칙의 조건 또는 결과를 확정하기 위해 추가 결정이 필요하다.

1. 외부 콘텐츠의 동일성을 판정할 플랫폼별 식별자와 URL 정규화 기준
2. 동기화 실패 후 재시도 간격, 대상 기간과 한 번에 처리할 수 있는 콘텐츠 수
3. 장소와 이벤트 개최의 상세 중복 판정 기준
4. 이벤트 유형을 카테고리와 분리할지 여부
5. 개최 시작일 또는 종료일 중 하나만 없는 이벤트 개최의 상태 계산 기준
6. 닉네임에서 허용하거나 제한할 문자 범위
7. 공유 보관함 이름의 길이와 중복 허용 여부
8. 보관함 초대의 유효기간, 재발급 방식, 취소 가능 여부와 사용 가능 횟수
9. 공유 보관함 권한 수준별 조회·수정·저장·삭제·초대·역할 변경 가능 범위
10. 공유 보관함의 복수 소유자 허용 여부와 마지막 소유자의 역할 변경·탈퇴 제한
11. 추천 조건에서 출발지가 필수인지 여부
12. 동일한 방문지 구성을 사용자가 의도적으로 별도 외출 코스로 저장할 수 있는지 여부
13. 외출 코스의 저장 관계가 삭제될 때 기존 일정이 유지되는지 여부
14. 이미 생성된 알림을 사용자가 관련 저장 항목을 삭제한 후에도 유지할지 여부
15. 전체 알림이 비활성화된 동안 발생한 알림을 나중에 소급 제공할지 여부
16. 랭킹 산정 기간, 지표별 가중치, 동률 처리와 갱신 주기

## 규칙 적용 우선순위

- 데이터 유일성과 멱등성 규칙은 화면 동작이나 사용자 재시도 방식과 관계없이 항상 지켜야 한다.
- 권한 규칙은 저장·삭제·초대 같은 개별 행위 규칙보다 먼저 검증해야 한다.
- 알림 생성 규칙은 사용자 설정, 활성 저장 관계, 대상 일자 조건을 모두 만족할 때만 적용한다.
- 정책 결정 필요 사항이 확정되기 전에는 해당 조건을 구현체에서 임의로 확대 해석하지 않는다.

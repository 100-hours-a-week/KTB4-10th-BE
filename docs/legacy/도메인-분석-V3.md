# KulInOne V3 도메인 분석 및 사전

## 1. 문서 목적

본 문서는 KulInOne V3 화면 설계서에 등장하는 업무 개념을 도메인별로 구분하고, 기획·디자인·프론트엔드·백엔드에서 같은 용어를 같은 의미로 사용하기 위한 기준을 정의한다.

이 문서는 API 명세, ERD, 상태 코드, 기술 스택을 확정하는 문서가 아니다. 후속 설계에서 필요한 개념과 경계를 합의하기 위한 초안이다.

## 2. 작성 기준

- 기준 범위는 Figma의 `V3` 프레임 내부로 한정한다.
- V1·V2는 V3 용어가 모호한 경우에만 참고하며, V3에 없는 기능을 추가하는 근거로 사용하지 않는다.
- 화면 명칭과 도메인 명칭을 구분한다. 예를 들어 `마이페이지`는 여러 도메인 정보를 모아 보여주는 화면이지, 독립된 핵심 업무 객체를 의미하지는 않는다.
- 사용자에게 보이는 문구와 시스템 내부 상태를 구분한다.
- 외부 관광 데이터의 식별자와 KulInOne 내부 식별자를 구분한다.
- 동일한 용어는 화면 설계서, ERD, API, 코드에서 같은 의미로 사용한다.

## 3. 도메인 구분

도메인은 화면이나 기술 기능이 아니라, 고유한 비즈니스 규칙과 데이터 생명주기를 가지는지를 기준으로 나눈다. V3는 **7개 주 도메인**과 **1개 하위 도메인**으로 구분한다. `공유·가져오기`는 논리적 경계는 표시하되, 현재 구현에서는 `가이드북·일정` 모듈 안에 두는 것을 기본으로 한다.

| ID | 분류 | 도메인 | 영문명 | 정의 | 핵심 책임 | 도메인 경계 |
|---|---|---|---|---|---|---|
| DOM-01 | 주 도메인 | 회원·인증 | Membership & Authentication | 서비스를 사용하는 회원과 외부 소셜 계정의 인증 관계를 관리하는 영역 | 소셜 로그인, 세션, 회원 상태, 프로필, 로그아웃, 탈퇴 | 취향 내용은 취향 도메인이 소유한다. 회원 화면의 푸시 수신 설정은 알림 도메인이 소유한다. |
| DOM-02 | 주 도메인 | 취향 | Preference | 회원이 선호하는 관광 카테고리와 여행 스타일을 표현하는 영역 | 최초 취향 저장, 기본 취향 조회·수정, 가이드북 생성에 사용할 기본 취향 제공 | 회원별 기본 취향 프로필 하나를 소유한다. V3에는 프로필과 분리된 여행별 취향이 정의되어 있지 않다. |
| DOM-03 | 주 도메인 | 관광 콘텐츠 | Tourism Content | 탐색·지도·일정에서 공통으로 사용되는 장소와 행사 정보의 기준 영역 | 장소, 행사, 분류, 위치, 기간, 운영 정보, 이미지, 외부 출처 | 관광 콘텐츠의 원본을 소유한다. 검색·필터·지도 표현은 탐색·지도가, 랭킹은 평가·랭킹이 담당한다. |
| DOM-04 | 주 도메인 | 탐색·지도 | Discovery & Map | 회원이 관광 콘텐츠를 검색·필터링하고 지도에서 확인하는 영역 | 검색 조건, 필터, 결과 목록, 현재 위치, 지도 범위, 마커, 클러스터, 즐겨찾기 | 관광 콘텐츠의 원본을 수정하지 않고 조회 결과를 구성한다. 마커·클러스터는 독립된 관광 콘텐츠가 아닌 조회·표현 모델이다. |
| DOM-05 | 주 도메인 | 가이드북·일정 | Guidebook & Itinerary | 회원의 여행 조건과 기본 취향을 이용해 일자별 방문 일정을 생성·보관·조회하는 영역 | 여행 조건, 생성 요청, 생성 작업, 가이드북, 일차, 일정 항목, 방문 순서, 핀 메타데이터 | 장소 기본 정보는 관광 콘텐츠가 소유하고, 가이드북은 여행 맥락과 방문 순서를 소유한다. 공유·가져오기를 하위 도메인으로 포함한다. |
| DOM-05-S | 하위 도메인 | 공유·가져오기 | Sharing & Import | 가이드북을 다른 사용자에게 전달하고 받은 가이드북을 자신의 가이드북으로 추가하는 영역 | 공유 링크, 만료, 가져오기, 중복 방지, 복사본 소유권, 파일 공유 | 가이드북 없이 독립적으로 존재할 수 없다. 현재는 DOM-05 내부 모듈로 구현하고, 규칙과 데이터가 확장되면 분리할 수 있다. |
| DOM-06 | 주 도메인 | 평가·랭킹 | Rating & Ranking | 종료된 여행의 방문 장소를 평가하고 집계 결과로 순위를 산정하는 영역 | 평가 요청, 평가 세션, 장소 별점, 건너뛰기, 제출, 집계 기간, 보정 점수, 랭킹 | 별점은 원본 데이터이고 랭킹은 별점으로부터 계산되는 파생 결과다. 정보 화면에서 진입해도 탐색 필터에 포함시키지 않는다. |
| DOM-07 | 주 도메인 | 알림 | Notification | 회원에게 평가, 공유, 가이드북 처리 등의 사건을 알리는 영역 | 알림, 알림 유형, 읽음, 모두 읽음, 푸시 설정 | 알림은 원본 사건을 대체하지 않는다. 푸시 설정은 마이페이지에서 노출되더라도 알림 도메인이 소유한다. |

생성권·상품·주문·결제는 V3 프레임에서 독립된 업무 흐름과 규칙이 확인되지 않으므로 현재 도메인 범위에 포함하지 않는다. 향후 V3 범위에 결제·환불·생성권 차감 규칙이 추가되면 별도 도메인으로 재검토한다.

## 4. 도메인 간 핵심 관계

| 주체 | 관계 | 대상 | 설명 |
|---|---|---|---|
| 회원 | 1:1 | 취향 프로필 | 회원은 현재 상시 적용되는 취향 프로필을 갖는다. |
| 가이드북 생성 요청 | N:1 | 취향 프로필 | 가이드북 생성은 회원의 기본 취향을 사용한다. V3에는 별도의 여행별 취향이 정의되어 있지 않다. |
| 회원 | 1:N | 가이드북 | 회원은 여러 가이드북을 소유할 수 있다. |
| 회원 | N:M | 관광 콘텐츠 | 즐겨찾기를 매개로 회원과 장소·행사가 연결된다. |
| 가이드북 | 1:N | 일차 | 가이드북은 여행 기간에 따른 일차를 갖는다. |
| 일차 | 1:N | 일정 항목 | 하나의 일차에는 방문 순서를 가진 여러 일정 항목이 속한다. |
| 일정 항목 | N:1 | 관광 콘텐츠 | 일정 항목은 방문할 장소 또는 행사를 참조한다. |
| 가이드북 | 1:N | 공유 링크 | 같은 가이드북에 대해 여러 공유 링크가 발급될 수 있다. |
| 공유 링크 | 1:N | 가져오기 기록 | 여러 회원이 하나의 유효한 링크를 통해 가이드북을 가져올 수 있다. |
| 회원+가이드북 | 1:1 | 평가 세션 | 한 회원의 한 여행에 대한 평가 진행 단위다. |
| 평가 세션 | 1:N | 장소 별점 | 방문한 일정 항목별로 별점 또는 건너뛰기 결과를 갖는다. |
| 장소 | 1:N | 장소 별점 | 한 장소에 여러 회원의 제출된 별점이 누적된다. |
| 회원 | 1:N | 알림 | 알림은 수신 회원별로 읽음 상태를 갖는다. |

## 5. 공통 값 개념

| 한글 명칭 | 영문명 | 정의 | 표현 형식 |
|---|---|---|---|
| 식별자 | Identifier / ID | 시스템 내에서 객체를 유일하게 식별하는 값 | 외부에는 의미를 담지 않는 식별자 사용 권장 |
| 날짜 | Date | 시간대와 무관한 달력상 날짜 | `YYYY-MM-DD` |
| 시간 | Time | 특정 날짜와 분리된 하루 내 시간 | `HH:mm` 또는 `HH:mm:ss` |
| 일시 | DateTime | 날짜와 시간이 결합된 특정 시점 | ISO 8601, 저장 기준은 UTC 권장 |
| 날짜 범위 | DateRange | 시작일과 종료일로 구성된 기간 | `{ startDate, endDate }`, 양 끝 포함 |
| 시간 범위 | TimeRange | 시작 시간과 종료 시간으로 구성된 범위 | `{ startTime, endTime }` |
| 시간대 | TimeZone | 일시를 해석할 지역 기준 | V3 국내 서비스는 `Asia/Seoul` |
| 지역 코드 | RegionCode | 행정구역을 식별하는 표준 코드 | 행정구역 코드 기준, 화면에는 명칭 표시 |
| 좌표 | Coordinates | 지도상 한 지점의 위도와 경도 | `{ latitude, longitude }` |
| 다각형 영역 | GeoPolygon | 여행 지역이나 화면에 표시할 지리적 경계 | 좌표 목록 또는 표준 지리 형식 |
| 거리 | Distance | 두 지점 사이의 거리 | 미터(m) 단위로 저장, 화면에서 m/km 변환 |
| 별점 | RatingValue | 사용자가 방문 장소에 부여한 평가 값 | 1∼5의 정수로 가정, 최종 기획 확정 필요 |
| 점수 | Score | 별점 집계로부터 계산된 순위 산정용 값 | 실수, 화면 표시 자릿수는 별도 정의 |
| 순위 | Rank | 동일한 집계 조건에서 정렬된 위치 | 1부터 시작하는 정수 |
| URL | URL | 이미지, 출처, 공유 링크 등의 위치 | HTTPS URL |
| 만료 일시 | ExpiresAt | 링크나 임시 자원을 사용할 수 없게 되는 시점 | DateTime |
| 생성·수정 일시 | CreatedAt / UpdatedAt | 객체가 생성되거나 마지막으로 수정된 시점 | DateTime |

## 6. 도메인 용어 사전

### 6.1 회원·인증

| 한글 명칭 | 영문명 | 정의 | 표현·식별 기준 |
|---|---|---|---|
| 회원 | Member | KulInOne에 가입하여 취향, 가이드북, 평가 등의 개인화 데이터를 소유하는 사용자 | `memberId` |
| 소셜 계정 | SocialAccount | 인증 제공자에서 발급한 계정과 KulInOne 회원의 연결 정보 | `provider + providerUserId` 조합으로 유일 |
| 인증 제공자 | AuthProvider | 회원 신원을 확인하는 외부 서비스 | V3: `KAKAO`, `GOOGLE` |
| 로그인 세션 | LoginSession | 인증된 회원의 앱 사용 상태를 유지하는 기간성 개념 | 회원, 발급 시각, 만료 시각 |
| 회원 상태 | MemberStatus | 회원의 현재 서비스 이용 가능 여부 | `ACTIVE`, `WITHDRAWN` 우선 검토 |
| 프로필 | Profile | 마이페이지에 표시되는 회원의 기본 정보 | 닉네임, 프로필 이미지 등 |
| 회원 탈퇴 | MembershipWithdrawal | 회원의 서비스 이용을 종료하고 계정을 탈퇴 상태로 전환하는 행위 | 탈퇴 일시와 처리 정책 구분 |

### 6.2 취향

| 한글 명칭 | 영문명 | 정의 | 표현·식별 기준 |
|---|---|---|---|
| 취향 프로필 | PreferenceProfile | 회원의 상시 관광 선호를 표현하는 현재값 | 회원별 1개 |
| 취향 대분류 | PreferenceCategory | 취향을 넓은 기준으로 묶은 분류 | 분류 코드와 명칭 |
| 취향 중분류 | PreferenceSubcategory | 대분류 아래의 구체적인 선호 항목 | 반드시 하나의 대분류에 속함 |
| 여행 스타일 | TravelStyle | 여행의 속도, 밀도, 활동 방식 등에 대한 선호 | 복수 선택 가능 여부는 기획 확정 필요 |
| 최초 취향 설정 | InitialPreferenceSetup | 최초 로그인 후 회원의 기본 취향 프로필을 만드는 과정 | 완료 여부와 완료 일시 |
| 기본 취향 수정 | PreferenceProfileUpdate | 마이페이지 또는 GUIDE-02에서 회원의 기본 취향을 변경하는 행위 | 어느 경로에서 저장해도 동일한 프로필 기본 취향을 갱신 |

### 6.3 관광 콘텐츠

| 한글 명칭 | 영문명 | 정의 | 표현·식별 기준 |
|---|---|---|---|
| 관광 콘텐츠 | TourismContent | 탐색, 지도, 가이드북, 평가에서 공통으로 참조하는 관광 대상의 상위 개념 | `contentId`, `contentType` |
| 장소 | Place | 좌표와 주소를 갖고 방문할 수 있는 물리적 대상 | `placeId` |
| 행사·축제 | Event | 특정 장소에서 정해진 기간에 개최되는 관광 콘텐츠 | `eventId`, 개최 기간 필수 |
| 문화유산 | CulturalHeritage | 관광 콘텐츠의 분류 중 문화유산에 해당하는 대상 | 분류 코드 |
| 명소 | Attraction | 관광 콘텐츠의 분류 중 상시 방문할 수 있는 주요 장소 | 분류 코드 |
| 콘텐츠 유형 | ContentType | 화면 표시와 필터에 사용하는 관광 콘텐츠 분류 | V3: `CULTURAL_HERITAGE`, `EVENT_FESTIVAL`, `ATTRACTION` |
| 행사 기간 | EventPeriod | 행사가 실제로 개최되는 시작일부터 종료일까지의 기간 | DateRange |
| 운영 시간 | OperatingHours | 특정 요일이나 날짜에 방문 가능한 시간 범위 | 요일+시간 범위 목록 |
| 주소 | Address | 관광 콘텐츠의 행정적·도로명 위치 표현 | 시도, 시군구, 상세 주소 분리 권장 |
| 콘텐츠 위치 | ContentLocation | 장소나 행사를 지도에 표시하기 위한 주소와 좌표 | Address + Coordinates |
| 콘텐츠 이미지 | ContentImage | 카드와 상세 화면에 표시할 관광 콘텐츠 이미지 | 원본 URL, 대체 이미지 여부 |
| 외부 콘텐츠 ID | ExternalContentId | 외부 관광 데이터 제공자가 부여한 식별자 | `source + externalId` 조합으로 유일 |
| 콘텐츠 출처 | ContentSource | 관광 정보를 제공한 외부 원천 | V3 표시 기준: TourAPI 등 |
| 원천 갱신 일시 | SourceUpdatedAt | 외부 원천에서 해당 콘텐츠가 마지막으로 갱신된 시점 | DateTime; 내부 `updatedAt`과 구분 |

### 6.4 탐색·지도

## 7. 핵심 용어 구분 기준

| 혼동하기 쉬운 용어 | 구분 기준 |
|---|---|
| 장소 vs 행사 | 장소는 물리적 위치가 핵심이고, 행사는 개최 기간과 내용이 핵심이다. 행사는 특정 장소에서 열릴 수 있다. |
| 카테고리 vs 취향 | 카테고리는 콘텐츠의 분류이고, 취향은 사용자가 선호하는 분류·스타일의 조합이다. |
| 가이드북 vs 일정 | 가이드북은 하나의 여행 전체를 나타내고, 일정은 그 안의 일차별 방문 계획을 나타낸다. |
| 일정 항목 vs 장소 | 일정 항목은 어느 날에 몇 번째로 방문하는지를 가진 여행 맥락이고, 장소는 여러 일정에서 재사용되는 기준 정보다. |
| 기본 취향 vs 여행 조건 | 기본 취향은 회원이 선호하는 카테고리·스타일이고, 여행 조건은 가이드북 생성을 위해 입력하는 지역·기간·동행·인원이다. V3에는 독립된 여행별 취향이 없다. |
| 원본 가이드북 vs 가져온 가이드북 | 가져오기가 완료되면 받는 회원이 소유하는 별도 복사본이 생성된다. 원본의 후속 변경이 복사본에 자동 반영되는 공동 편집 모델이 아니다. |
| 별점 vs 보정 평점 | 별점은 한 회원이 남긴 원본 평가값이고, 보정 평점은 여러 별점과 평가 수로 계산한 랭킹용 파생값이다. |
| 평가 건너뛰기 vs 평가 자동 요청 안 함 | 전자는 특정 장소만 평가하지 않는 것이고, 후자는 해당 여행의 자동 평가 안내 자체를 다시 노출하지 않는 선택이다. |
| 랭킹 vs 탐색 목록 | 탐색 목록은 관광 콘텐츠를 검색·필터링한 결과고, 랭킹은 제출된 평가를 특정 기간과 지역 기준으로 집계한 별도 조회 결과다. |
| 푸시 알림 vs 인앱 알림 | 푸시는 OS를 통한 전송 방식이고, 인앱 알림은 앱 안에 저장·표시되는 수신 항목이다. |

## 8. 도메인 불변 규칙

1. 하나의 KulInOne 회원은 동일한 인증 제공자의 동일한 외부 계정과 중복 연결될 수 없다.
2. 외부 콘텐츠 ID는 내부 ID를 대체하지 않는다. 외부 원천과 외부 ID를 함께 저장해 동기화와 출처 추적에 사용한다.
3. 행사는 시작일과 종료일을 갖는다. 종료일은 시작일보다 빠를 수 없다.
4. 여행 종료일은 시작일보다 빠를 수 없고, 가이드북의 일차는 여행 기간 범위 안에만 속한다.
5. 일차 내 방문 순서는 중복될 수 없다.
6. 가이드북 생성은 회원의 기본 취향을 사용한다. GUIDE-02에서 취향을 수정해 저장하는 경우에도 회원의 기본 취향을 갱신하며, 여행별 독립 취향으로 저장하지 않는다.
7. 가이드북 생성 작업은 앱 종료와 무관하게 서버에서 계속될 수 있는 독립된 처리 단위로 보는 것이 적절하다.
8. 공유로 가져온 가이드북은 받는 회원이 소유하는 새 가이드북이다. 원본과 같은 ID를 사용하지 않는다.
9. 만료되거나 폐기된 공유 링크로는 미리보기나 가져오기를 완료할 수 없다.
10. 동일한 회원이 동일한 원본 가이드북을 반복해 가져오더라도 중복 복사본이 무제한으로 생성되지 않도록 멱등성 기준이 필요하다.
11. 평가 자동 요청은 여행 종료 후에만 대상이 된다.
12. 한 회원은 한 가이드북의 하나의 일정 항목에 대해 하나의 최종 별점만 가진다. 이전·다음으로 돌아가는 동안은 수정 가능하다.
13. 랭킹 산정에는 제출된 유효 별점만 포함하고, 미평가·건너뛰기·임시 저장은 포함하지 않는다.
14. 주간·월간 랭킹의 집계 기간은 평가 제출일이 아니라 일정의 방문일을 기준으로 한다.
15. 랭킹 검색은 이미 산정된 랭킹에서 항목을 좁히는 행위이다. 검색 결과에 1위부터 새로 순위를 부여하지 않는다.
16. 랭킹은 원본 데이터가 아니라 별점으로부터 계산되는 파생 결과이다. 장소 별점이 바뀌면 랭킹 결과는 재산정될 수 있다.
17. 푸시 알림을 끄더라도 인앱 알림 및 서비스 내 토스트를 표시할 수 있다. 푸시 설정은 도메인 사건의 생성 자체를 막지 않는다.
18. 알림은 사건을 알리는 보조 수단이다. 알림이 누락되거나 전송에 실패해도 가이드북 생성·공유·평가 등 원본 상태는 유지되어야 한다.

## 9. 화면과 도메인의 관계

| V3 화면 영역 | 주요 도메인 | 해석 |
|---|---|---|
| 로그인 | 회원·인증 | 소셜 계정으로 회원을 인증한다. |
| 최초 취향 선택 | 취향 | 회원의 상시 취향 프로필을 최초 생성한다. |
| 맵 | 탐색·지도, 관광 콘텐츠, 가이드북·일정 | 일반 관광 마커와 가이드북 일정 핀의 맥락을 구분한다. |
| 정보—둘러보기 | 탐색·지도, 관광 콘텐츠 | 검색어·지역·월·카테고리로 콘텐츠를 조회한다. |
| 정보—랭킹 보기 | 평가·랭킹, 관광 콘텐츠 | 주간·월간 보정 평점으로 산정된 순위를 조회한다. |
| 가이드 | 가이드북·일정(공유·가져오기 하위 도메인), 평가·랭킹 | 생성·목록·상세·공유·평가 진입을 포함한다. |
| 마이페이지 | 회원·인증, 취향, 가이드북·일정, 알림 | 독립 도메인이 아니라 여러 도메인의 회원 관련 정보를 모아 보여주는 조합 화면이다. |
| 알림함 | 알림 | 수신 알림을 시간순으로 조회하고 읽음 상태를 변경한다. |

## 10. 후속 설계 전 확정할 용어·경계

아래 항목은 현재 도메인에서 필요하지만 V3 화면만으로 정확한 값을 확정하기 어려운 부분이다.

1. 월 필터의 적용 대상: 행사에만 적용할지, 명소·문화유산의 기간성 정보에도 적용할지.
2. 월 필터의 연도 기준: 현재 연도, 앞으로 12개월, 전체 연도 중 어떤 범위를 의미하는지.
3. 행사 검색 시 기간 중첩 기준: 행사 기간의 하루라도 해당 월과 겹치면 포함할지.
4. 취향 대분류·중분류·여행 스타일의 최종 코드 목록과 복수 선택 규칙.
5. 기본 취향을 수정했을 때 이미 생성된 가이드북 카드의 취향 표시를 유지할지, 현재 기본 취향으로 바꿀지. 현재 V3에는 이 데이터 보존 규칙이 명시되어 있지 않다.
6. 가이드북 생성 상태와 진행 단계의 최종 목록, 재시도 가능 여부.
7. 일정 항목이 장소만 참조하는지, 행사 개최 회차까지 구분해 참조해야 하는지.
8. ‘방문한 장소’를 판단하는 방법: 일정 포함만으로 간주할지, 위치·사용자 확인 등이 필요한지.
9. 별점 범위와 단위: 1∼5점 정수인지, 0.5점 단위를 허용하는지.
10. 평가 제출 후 수정 가능 여부와 수정 가능 기간.
11. 주간 랭킹의 주 기준: 월요일∼일요일 등 시작·종료 요일과 `Asia/Seoul` 마감 시각.
12. 랭킹 집계 그룹: 전국 전체 평균을 `C`로 쓸지, 선택 지역 평균을 쓸지.
13. 신뢰 기준값 `m`의 초기값, 변경 주체, 변경 이력 보관 여부.
14. 보정 평점이 같은 장소의 동순위 처리 기준: 평가 수, 원평균, 최근 평가 등.
15. 공유로 가져오기 후 원본 변경·삭제가 복사본에 영향을 주지 않는다는 정책의 최종 확정.
16. 파일 공유의 실제 파일 형식, 링크 발급 방식, 보관·만료 정책.
17. 회원 탈퇴 시 가이드북, 공유 링크, 별점, 즐겨찾기, 알림의 유지·익명화·삭제 정책.

## 11. 해석상 유의사항

- `마이페이지`, `정보`, `맵`, `가이드`는 하단 탭 또는 화면 영역의 명칭이다. ERD의 엔티티명으로 그대로 사용하지 않는다.
- `랭킹 보기`는 정보 화면에서 진입하지만, 일반 탐색의 필터가 아니다. 평가·랭킹 도메인의 별도 조회 모드로 본다.
- `지도`, `검색`, `페이지네이션`은 관광 콘텐츠의 원본을 소유하는 도메인이 아니라, 탐색·지도 도메인의 조회·표현 기능이다.
- `공유·가져오기`는 고유한 만료·중복 방지·복사본 규칙을 가지지만, 가이드북을 대상으로만 동작하므로 V3에서는 가이드북·일정의 하위 도메인으로 본다.
- `현재 위치`는 일반 설정 도메인이 아니라 탐색·지도의 입력값이다. `푸시 수신 설정`은 알림 도메인의 정책이다.
- 생성권·결제는 V3 범위에서 독립 도메인으로 정의하지 않는다.
- `전체`는 특정 지역·월·카테고리를 선택하지 않은 조회 조건이며, 독립된 업무 객체가 아니다.
- `검색 결과 없음`, `랭킹 결과 없음`, `알림 없음`은 엔티티 상태가 아니라 조회 결과가 0개인 화면 상태다.
- 정렬 순서와 페이지네이션은 조회 규칙이며 개별 도메인 객체의 속성으로 두지 않는다.
- 화면에 표시되는 문구는 바뀐 수 있으나, 이 문서에서 정의한 도메인 용어의 의미는 바뀌어서는 안 된다.

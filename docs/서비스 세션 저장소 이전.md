# 서비스 세션의 Redis 전환

## 결정과 범위

기준은 BR-MEM-02/03/12, FR-MEM-02, BR-NOT-08/11/12/16이다.
선행 #285/#286과 #287/#288은 기본 경로를 바꾸지 않는 준비 단계였다.
이번 구현은 해당 어댑터를 실제 로그인·인증·로그아웃·탈퇴에 연결하고 MySQL 세션 테이블을 제거한다.

- 세션 생성·검증·활동 갱신·만료·폐기: Redis
- 최신 회원 상태·탈퇴 여부: 인증마다 MySQL `members` SELECT 1회
- Push 구독: MySQL 유지. 발송은 회원·구독 상태 기준이고 Redis 세션 존재를 요구하지 않는다.
- SSE 연결: 각 서버 메모리 유지. 다른 인스턴스의 종료는 기존 Redis Pub/Sub로 전달한다.
- 연결 식별자는 원문 랜덤 쿠키 토큰의 SHA-256 소문자 hex다. 숫자 ID·카운터를 만들지 않는다.
- Spring Session은 기존 OAuth 임시 `JSESSIONID` 용도를 유지한다. 서비스 쿠키 `KGB_SESSION`과 분리한다.
- 쿠키·CSRF·회원당 한 세션·절대 8시간·유휴 30분 정책은 유지한다.

## 인증 흐름과 데이터 계약

`ServiceSessionService.authenticate`가 쿠키를 SHA-256으로 변환한다.
Redis 인증 Lua가 유효성을 검사하고 활동 시각/TTL을 원자적으로 갱신한 뒤 회원 ID만 반환한다.
그 회원 ID로 `findByIdAndDeletedAtIsNull`를 호출하여 최신 상태를 읽고
`AuthenticatedMember(memberId, status, sessionHash)`를 구성한다.

기존 세션·회원 JOIN, MySQL 세션 행 잠금과 활동 UPDATE는 없다.
온보딩 완료는 회원 테이블만 변경하면 다음 인증에 바로 반영된다. 회원 상태 캐싱·동기화는 하지 않는다.
Redis에 없는 세션은 MySQL에서 복원하지 않는다. 저장소 장애는 인증 실패로 숨기거나 우회하지 않는다.

| 키 | 자료형·값 | 수명 |
| --- | --- | --- |
| `<namespace>:session:<hash>` | Hash: schemaVersion=2, memberId, createdAtEpochMillis, expiresAtEpochMillis, lastUsedAtEpochMillis | min(유휴 제한, 절대 잔여) |
| `<namespace>:member-session:<memberId>` | String: 현재 세션 해시 | 절대 만료까지, 활동으로 연장하지 않음 |

namespace는 `SERVICE_SESSION_REDIS_NAMESPACE`로 설정한다.
기본값은 local/prod별 `kgb:<env>:service-session:v2`이며 OAuth namespace와 다르다.
이전 준비 단계 schema 1의 숫자 sessionId·memberStatus·memberDeleted·revoked 필드는 사용하지 않는다.
Redis TIME을 기준으로 시각을 처리한다. 회원 ID는 문자열로 보존해 Lua 숫자 정밀도 손실을 막는다.

## 발급·재로그인·로그아웃·탈퇴

- 로그인은 회원 생성/생성권 지급과 회원 행 잠금을 유지한 상태에서 Redis 발급·교체 Lua를 호출한다.
  새 세션 Hash·회원 인덱스를 갱신하고 이전 Hash를 삭제한다. 이전 Push 구독을 일괄 폐기하지 않는다.
  DB 트랜잭션 완료 후 커밋·롤백 여부와 무관하게 교체된 이전 해시의 로컬 SSE를 종료하고 SESSION_DISCONNECTED를 발행한다.
  Redis fan-out 사용 시 다른 인스턴스도 해당 해시의 연결만 종료한다. 새 세션 연결은 유지한다.
  이전 Redis 세션은 DB 롤백으로 복원되지 않으므로 롤백 시에도 이전 SSE를 정리한다.
  종료·전파 실패는 기록하고 트랜잭션 결과를 뒤집지 않는다. 새 세션 롤백 보상 실패도 이전 SSE 정리를 막지 않는다.
  Pub/Sub은 best-effort이므로 장애 시 다른 인스턴스의 즉시 종료를 보장하거나 재전송하지 않는다.
- DB 작업이 롤백되면 transaction synchronization이 새 해시의 세션을 보상 폐기한다.
  이미 더 새 로그인으로 교체된 인덱스를 삭제하지 않는다. 보상 자체가 실패하면 오류를 기록한다.
- 로그아웃은 회원 행 잠금 아래 현재 해시의 Redis 세션을 폐기하고
  MySQL에서 `member_id + session_hash`가 일치하는 활성 Push 구독만 폐기한다.
  컨트롤러는 동일 해시의 로컬 SSE 연결 종료·Pub/Sub 발행·쿠키/CSRF 정리를 수행한다.
- Push 등록도 같은 회원 행을 잠그고 Redis 세션의 소유권을 재확인하여
  로그아웃과 등록이 교차해 폐기된 세션으로 구독이 등록되지 않도록 한다.
- 탈퇴는 기존 카카오 연결 해제·회원 소프트 삭제·생성권/작업/Push 정리에 Redis 회원 세션 폐기를 연결한다.
  탈퇴 회원은 매 요청 DB 조회로 차단되므로 Redis에 회원 상태를 복사하지 않는다.
- 자연 만료는 Push 구독을 폐기하지 않는다. 로그인 재개 시 과거 Push 재발송도 없다.
- SSE는 재로그인 트랜잭션 완료 후 커밋·롤백 모두 이전 연결을 정리한다. 열린 연결의 heartbeat는 주기적 세션 재인증을 하지 않으므로 자연 만료 시 즉시 종료는 보장하지 않는다.

## 오류·동시성·복구의 경계

Lua는 다른 Redis 명령과의 끼어들기를 막지만 MySQL과의 분산 트랜잭션은 아니다.
Redis 발급/폐기 실패는 성공 로그인/로그아웃으로 응답하지 않는다.
발급 뒤 DB 롤백 시 새 세션 정리를 시도하지만 이전 세션까지 복원하지 않는다.
로그아웃에서 Redis 폐기 뒤 DB 커밋이 실패하면 인증은 차단돼도 Push 구독 정리는 미완료일 수 있다.
보상 실패/불확실한 커밋은 자동 재발급하지 않고 오류 모니터링과 운영 재정리가 필요하다.
이 드문 부분 실패를 영속 재시도로 보장하려면 별도 outbox/정리 작업이 필요하며 이번 변경은 이를 보장하지 않는다.

회원 인덱스와 세션 Hash는 독립 eviction을 허용하면 안 된다.
운영 Redis는 noeviction/메모리 경보·영속화·복구 정책을 확인해야 한다.
현재 Standalone Redis만 지원하며, 인덱스로 동적으로 이전 키를 찾아 접근하므로
Redis Cluster 전환에는 키 배치/hash tag 설계가 별도로 필요하다.

## 스키마와 운영 전환

`V14__move_service_sessions_to_redis.sql`은 다음 순서로 동작한다.

1. Push 구독에 `session_hash VARCHAR(64)` 추가
2. 기존 `auth_sessions.session_id_hash`를 hex로 변환해 모든 구독에 이관 (ACTIVE/REVOKED 모두 보존)
3. 구독의 숫자 세션 FK·컬럼을 제거하고 해시 인덱스 적용
4. `auth_sessions` 테이블 삭제

기존 migration은 변경하지 않는다. 운영 DB/Redis에 이 변경을 실행하거나 기존 데이터를 삭제하지 않았다.
구버전 앱은 새 스키마와 호환되지 않으므로 구/신 버전을 섞은 rolling 전환은 금지한다.
배포 전 DB 백업·구버전 중지·Redis 설정·migration 수행·신버전 시작 순서를 확정해야 한다.

이 변경에는 기존 로그인 세션을 Redis로 자동 이관하는 도구가 없다.
세션 이관 없이 전환하면 기존 쿠키는 인증되지 않아 한 번 재로그인이 필요하다.
기존 Push 구독은 해시와 상태를 보존하므로 자연 만료와 동일하게 발송 가능하다.
무중단 세션 유지가 필요하면 테이블 삭제 전에 별도 사전 이관을 설계해야 하며, 운영 전환은 그 결정 이후에 수행한다.
테이블 삭제 후 구버전으로의 단순 코드 롤백은 불가하다. 백업 복구를 포함한 별도 절차가 필요하다.

## 검증과 산출물

- 실제 Redis: Hash schema 2, 만료 경계, TTL 상한, 충돌/손상 거절, 회원별 교체·소유권·동시성
- 실제 MySQL: Flyway/JPA 검증, 기존 Push 구독 해시 backfill·상태/행 보존·세션 테이블 제거
- 인증 SQL 계측: 회원 SELECT 1개, INSERT/UPDATE 0개
- 온보딩 변경 후 Redis 동기화 없이 최신 회원 상태 인증
- DB 롤백 보상, Redis 발급 장애 시 신규 회원 작업 롤백
- Push 등록/로그아웃/탈퇴, SSE 종료·Pub/Sub 및 기존 API 회귀

요구사항·테이블 정의·ERD SQL·API 설명을 동기화한다.
화면/클라이언트 요청 계약은 변경하지 않아 Figma 원본은 수정하지 않았다.
운영 재로그인 전환에 대한 사용자 안내/화면 검증은 배포 결정 전에 별도로 필요하다.

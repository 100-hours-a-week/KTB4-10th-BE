# V1 테이블 정의서

이 문서는 Flyway migration `V1`, `V1_1`, `V2`, `V3`, `V4`를 순서대로 적용한 후의 실효 스키마를 정리한다. DB 구조의 최종 source of truth는 `src/main/resources/db/migration`이다.

- DBMS: MySQL 8.4
- Engine: InnoDB
- Charset/Collation: `utf8mb4` / `utf8mb4_0900_ai_ci`
- 시각: timezone 없는 `DATETIME(6)`에 UTC 저장
- 기본 PK: `BIGINT AUTO_INCREMENT`

## 1. 회원·인증

### `members`

회원의 OAuth 식별, 프로필, 온보딩 상태와 푸시 설정을 저장한다.

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| `id` | BIGINT | N | PK |
| `oauth_provider` | VARCHAR(20) | N | OAuth 공급자 Enum |
| `oauth_subject` | VARCHAR(255) | N | 공급자 회원 식별자 |
| `nickname` | VARCHAR(50) | N | 표시 이름 |
| `email` | VARCHAR(254) | Y | 표시용 이메일 |
| `profile_image_url` | VARCHAR(2048) | Y | 프로필 이미지 URL |
| `language_code` | VARCHAR(10) | N | 기본 `ko` |
| `status` | VARCHAR(20) | N | 기본 `ONBOARDING` |
| `push_enabled` | BOOLEAN | N | 기본 `TRUE` |
| `deleted_at` | DATETIME(6) | Y | 탈퇴 시각 |
| `created_at`, `updated_at` | DATETIME(6) | N | 생성·수정 시각 |

- UNIQUE: `(oauth_provider, oauth_subject)`
- INDEX: `(status)`

### `auth_sessions`

로그인 후 서비스 세션의 해시와 만료·폐기 상태를 저장한다.

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| `id` | BIGINT | N | PK |
| `member_id` | BIGINT | N | `members.id` FK |
| `session_id_hash` | BINARY(32) | N | 세션 ID SHA-256 해시 |
| `expires_at` | DATETIME(6) | N | 절대 만료 시각 |
| `revoked_at` | DATETIME(6) | Y | 폐기 시각 |
| `last_used_at` | DATETIME(6) | Y | 마지막 성공 인증 시각 |
| `created_at` | DATETIME(6) | N | 생성 시각 |

- UNIQUE: `(session_id_hash)`
- INDEX: `(member_id, revoked_at, expires_at)`

### `member_preferences`

회원이 선택한 기본 취향 Enum을 행 단위로 저장한다.

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| `id` | BIGINT | N | PK |
| `member_id` | BIGINT | N | `members.id` FK |
| `preference_type` | VARCHAR(20) | N | 취향 유형 |
| `preference_code` | VARCHAR(50) | N | 취향 코드 |

- UNIQUE: `(member_id, preference_type, preference_code)`
- INDEX: `(preference_type, preference_code)`

### `notifications`

회원에게 보여줄 미읽은 인앱 알림을 저장한다. 읽기 처리는 행 삭제로 표현한다.

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| `id` | BIGINT | N | PK |
| `recipient_member_id` | BIGINT | N | `members.id` FK |
| `type` | VARCHAR(30) | N | 알림 유형 |
| `title` | VARCHAR(100) | N | 제목 |
| `body` | VARCHAR(500) | N | 본문 |
| `reference_type` | VARCHAR(30) | Y | 연결 대상 유형 |
| `reference_id` | VARCHAR(50) | Y | 연결 대상 ID |
| `created_at` | DATETIME(6) | N | 생성 시각 |

- CHECK: `reference_type`과 `reference_id`는 둘 다 NULL이거나 둘 다 존재
- INDEX: `(recipient_member_id, created_at)`

## 2. 지역·관광 콘텐츠

### `regions`

광역 시·도와 하위 시·군·구를 2단계 계층으로 저장한다.

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| `id` | BIGINT | N | PK |
| `parent_id` | BIGINT | Y | 상위 `regions.id` FK |
| `administrative_code` | VARCHAR(20) | N | 서비스 행정 코드 |
| `name` | VARCHAR(100) | N | 지역명 |
| `region_level` | VARCHAR(20) | N | `PROVINCE` 또는 `DISTRICT` |

- UNIQUE: `(administrative_code)`
- CHECK: `PROVINCE`는 `parent_id IS NULL`, `DISTRICT`는 `parent_id IS NOT NULL`
- INDEX: `(parent_id, name)`

### `tour_api_region_mappings`

TourAPI 원본 지역 코드와 서비스 `regions`를 연결한다.

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| `id` | BIGINT | N | PK |
| `source_provider` | VARCHAR(30) | N | 원본 공급자 |
| `source_region_code` | VARCHAR(20) | N | 원본 광역 코드 |
| `source_district_code` | VARCHAR(20) | N | 원본 하위 지역 코드 |
| `region_id` | BIGINT | N | `regions.id` FK |
| `created_at`, `updated_at` | DATETIME(6) | N | 생성·수정 시각 |

- UNIQUE: `(source_provider, source_region_code, source_district_code)`
- INDEX: `(region_id)`

### `tourism_contents`

TourAPI에서 수집한 관광 콘텐츠 공통 원본을 저장한다. V4 적용 후 `category` 컬럼은 존재하지 않는다.

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| `id` | BIGINT | N | PK |
| `source_provider` | VARCHAR(30) | N | 원본 공급자 |
| `source_content_id` | VARCHAR(100) | N | 원본 콘텐츠 ID |
| `source_content_type_id` | VARCHAR(20) | Y | TourAPI 콘텐츠 타입 ID |
| `title` | VARCHAR(200) | N | 제목 |
| `description` | TEXT | Y | 설명 |
| `region_id` | BIGINT | N | `regions.id` FK |
| `source_region_code`, `source_district_code` | VARCHAR(20) | Y | TourAPI 지역 코드 |
| `classification_code_1`~`3` | VARCHAR(20) | Y | TourAPI 분류 코드 |
| `address` | VARCHAR(500) | Y | 주소 |
| `location` | POINT SRID 4326 | N | WGS84 좌표 |
| `phone` | VARCHAR(50) | Y | 전화번호 |
| `homepage_url`, `thumbnail_url` | VARCHAR(2048) | Y | 홈페이지·썸네일 URL |
| `source_created_at`, `source_modified_at` | DATETIME(6) | Y | 원본 생성·수정 시각 |
| `status` | VARCHAR(20) | N | 기본 `ACTIVE` |
| `deleted_at` | DATETIME(6) | Y | 소프트 삭제 시각 |
| `created_at`, `updated_at` | DATETIME(6) | N | 생성·수정 시각 |

- UNIQUE: `(source_provider, source_content_id)`
- INDEX: `(status, deleted_at, created_at DESC, id DESC)`
- INDEX: `(source_provider, source_region_code, source_district_code)`
- INDEX: `(region_id, classification_code_1)`
- SPATIAL INDEX: `(location)`

### `event_details`

행사 콘텐츠의 기간과 운영 정보를 1:1로 저장한다.

- 컬럼: `content_id` PK/FK, `start_date`, `end_date`, `operating_hours`, `organizer`, `updated_at`
- CHECK: `start_date <= end_date`

### `content_images`

관광 콘텐츠의 이미지와 표시 순서를 저장한다.

- 컬럼: `id`, `content_id` FK, `image_url`, `image_url_hash`, `sort_order`, `source_url`, `created_at`
- UNIQUE: `(content_id, image_url_hash)`
- INDEX: `(content_id, sort_order)`

### `favorite_contents`

회원과 관심 관광 콘텐츠의 N:M 관계를 저장한다.

- 컬럼: `id`, `member_id` FK, `content_id` FK, `created_at`
- UNIQUE: `(member_id, content_id)`

## 3. 가이드북 생성·보관

### `guidebooks`

AI가 생성한 가이드북 결과와 HTML 원문을 저장한다.

- 컬럼: `id`, `title`, `region_id` FK, `start_date`, `end_date`, `companion`, `people_count`, `content_html`, `version`, `created_at`, `updated_at`
- CHECK: `start_date <= end_date`, `people_count >= 1`, `version >= 1`

### `member_guidebooks`

회원이 보관 중인 가이드북과 획득 방식을 저장한다. 목록 삭제는 `deleted_at`으로 표현한다.

- 컬럼: `id`, `member_id` FK, `guidebook_id` FK, `acquisition_type`, `created_at`, `deleted_at`
- UNIQUE: `(member_id, guidebook_id)`
- CHECK: `acquisition_type IN ('CREATED', 'IMPORTED')`
- INDEX: `(member_id, deleted_at, created_at)`

### `generation_jobs`

AI 가이드북 생성 작업의 멱등성, 상태, 시도, AI 작업 ID와 결과 연결을 저장한다.

| 컬럼 그룹 | 컬럼 |
| --- | --- |
| 식별·연결 | `id`, `member_id` FK, `guidebook_id` FK, `ai_job_id` |
| 작업 정보 | `job_type`, `status`, `request_payload`, `error_payload` |
| 멱등·시도 | `idempotency_key`, `attempt_count`, `attempt_started_at`, `next_attempt_at` |
| lease | `lease_token`, `lease_version`, `lease_expires_at` |
| 시각 | `started_at`, `cancel_requested_at`, `completed_at`, `created_at`, `updated_at` |
| 파생 컬럼 | `active_member_id`: `PENDING`·`PROCESSING`일 때만 `member_id` |

- UNIQUE: `(member_id, idempotency_key)`
- UNIQUE: `(active_member_id)` — 회원당 활성 작업 하나
- UNIQUE: `(ai_job_id)` — NULL 허용
- CHECK: `attempt_count BETWEEN 0 AND 3`
- INDEX: `(member_id, status, created_at)`, `(guidebook_id, created_at)`, `(status, next_attempt_at)`, `(status, lease_expires_at)`

### `itinerary_days`

가이드북의 여행 일자를 저장한다.

- 컬럼: `id`, `guidebook_id` FK, `day_number`, `itinerary_date`
- UNIQUE: `(guidebook_id, day_number)`, `(guidebook_id, itinerary_date)`
- CHECK: `day_number >= 1`

### `itinerary_items`

일자별 방문 장소와 생성 시점 snapshot을 저장한다.

- 컬럼: `id`, `itinerary_day_id` FK, `tourism_content_id` nullable FK, `sequence`, `scheduled_time`, `place_snapshot` JSON, `created_at`
- UNIQUE: `(itinerary_day_id, sequence)`
- CHECK: `sequence BETWEEN 1 AND 20`
- INDEX: `(tourism_content_id)`

## 4. 생성권

### `credit_wallets`

회원별 현재 생성권 잔액을 저장한다.

- 컬럼: `id`, `member_id` FK, `credit_balance`, `created_at`, `updated_at`
- UNIQUE: `(member_id)`
- CHECK: `credit_balance >= 0`

### `credit_transactions`

V1 무료 생성권의 증감 이력과 처리 후 잔액을 불변 원장으로 저장한다.

- 컬럼: `id`, `wallet_id` FK, `type`, `credit_delta`, `credit_balance_after`, `generation_job_id` nullable FK, `idempotency_key`, `created_at`
- UNIQUE: `(idempotency_key)`
- CHECK: `credit_balance_after >= 0`
- INDEX: `(wallet_id, created_at)`
